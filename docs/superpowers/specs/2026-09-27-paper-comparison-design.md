# 논문 비교 모드 기능 명세

## 목적

챗봇이 벡터 검색으로 찾은 논문 중 2~4편을 사용자가 선택해 연구 문제, 방법, 데이터·실험 설정, 주요 결과를 한 화면에서 비교한다. 비교 답변은 저장된 제목과 초록만 근거로 하며, 근거가 부족한 항목은 추측하지 않고 확인 불가로 표시한다.

## 사용자 흐름

1. 사용자가 평소처럼 챗봇에 질문한다.
2. 해당 응답의 벡터 검색 결과가 2편 이상이면 응답 아래에 논문 비교 영역을 표시한다.
3. 사용자는 검색 결과에서 2~4편을 선택해 비교를 실행한다. 선택 목록에는 arXiv ID와 제목을 표시한다.
4. 앱은 선택한 각 논문의 제목·초록만 모델에 전달하고 구조화된 비교 결과를 요청한다.
5. 비교 표는 논문별 행으로 구성하고, 연구 문제·방법·데이터/실험 설정·주요 결과를 열로 보여 준다. 각 논문 행에는 출처 arXiv ID와 arXiv 페이지 링크를 표시한다.
6. 선택을 바꾸어 다시 비교할 수 있다. 비교 결과는 해당 대화 응답에 귀속하며 다른 질문의 검색 결과와 섞이지 않는다.

## 근거 및 출력 계약

- 입력 근거는 선택 논문의 arXiv ID, 제목, 초록뿐이다. PDF 전문을 읽거나 외부 메타데이터를 추가로 가져오지 않는다.
- 모델은 각 논문별로 `research_question`, `method`, `data_and_evaluation`, `key_findings`를 반환한다.
- 각 항목은 자연어 `text`와 그 문장을 뒷받침하는 `evidence_ids`로 구성한다. 근거가 없거나 초록에서 확인할 수 없으면 `text`는 한국어 `초록에서 확인할 수 없음`으로, 근거 ID는 빈 목록으로 둔다.
- 각 논문 행의 근거 ID는 그 행의 arXiv ID만 사용할 수 있다. 누락·중복·선택되지 않은 ID가 포함된 응답은 표시하지 않고 오류 안내를 낸다.
- 비교 결과는 요약·분류이며 논문 전문의 포괄적 검토나 과학적 타당성 판정으로 표현하지 않는다.

## 사용자 인터페이스

- 비교 UI는 기존 챗봇 응답에 포함된 `papers` 결과 아래에 표시한다.
- 표시 결과가 2편 미만이면 비교 UI를 제공하지 않는다. 2~4편 선택 규칙을 안내한다.
- 검색 결과에 필요한 필드가 없는 논문은 선택지에서 제외한다.
- 생성 중에는 중복 요청을 막고 진행 상태를 표시한다. 모델 오류·잘못된 구조·근거 검증 실패 시 답변을 임의 보정해 표시하지 않고 재시도 가능한 오류 메시지를 보인다.
- 기존 검색 답변, 번역, 근거 확인, 대화 초기화 동작은 유지한다.

## 범위 밖

- arXiv PDF 다운로드/전문 파싱, 신규 API·데이터베이스 스키마, 검색 알고리즘 변경, 자동 논문 선정은 포함하지 않는다.
- 비교표 파일 내보내기·공유·즐겨찾기 기능은 포함하지 않는다.
- 기존 RAG 평가 데이터셋과 평가 지표를 이번 기능을 위해 변경하지 않는다.

## 검증 기준

1. 2~4개 선택 제한, 입력 논문 순서 유지 및 필수 초록 필드 확인을 테스트한다.
2. 구조화 출력에서 선택하지 않은 ID, 누락된 행, 빈/잘못된 항목을 거부한다.
3. 근거가 없는 비교 항목은 확인 불가 문구와 빈 ID로 유지한다.
4. 유효 출력의 네 비교 항목 및 arXiv 링크 정보를 UI에 표시하는 경로를 테스트한다.
5. UI/검증 테스트는 Neo4j 및 유료 모델 호출 없이 실행되며, 전체 테스트·Ruff·Python 컴파일을 통과한다.

## 구현 범위

- `chatbot.py`: 비교용 구조화 스키마, 입력 조립, 모델 호출, 출력 검증을 추가한다.
- `app.py`: 검색 결과별 선택 UI, 비교 실행 상태, 표와 출처 링크 표시를 추가한다.
- `tests/`: 비교 입력·출력 검증 및 Streamlit 경로의 결정론적 테스트를 추가한다.
- README 문서는 실제 구현과 일치하도록 필요한 부분만 갱신한다.
