# RAG 평가 품질·비용·재현성 개선 설계

## 목표

arXiv GraphRAG의 답변 근거 인용을 명확히 분리하고, 검색·답변 비교 결과를 더 신뢰할 수 있게 만든다. 실행별 지연시간·토큰·설정 정보를 저장해 포트폴리오 평가와 후속 실험을 재현할 수 있게 한다.

## 현재 동작과 확인된 한계

- `GroundedAnswer`에는 `answer`, `evidence_ids`만 있다. 시스템 프롬프트는 관련 논문을 답변에 보고하도록 지시하고, 평가기는 정확한 제목 케이스의 gold ID 한 개와 전체 `evidence_ids`를 비교한다. 관련 논문을 포함한 정답 답변도 target citation precision을 낮출 수 있다.
- `app.py`는 답변 아래에 개인화 PageRank 관련 논문 표를 별도로 그린다. 따라서 답변 모델의 Related papers 목록은 중복이며 주 답변 근거와 관계 논문 ID를 혼합한다.
- 현재 토픽 평가 10건은 자동 생성된 넓은 정답 ID 목록을 사용하며 필수 사실 문구 라벨은 비어 있다. 이 자료만으로 답변 사실성이나 전문가 관련성을 채점할 수 없다.
- 비교 평가는 평균 지연시간과 채팅 토큰을 기록하지만 p50/p95, 임베딩 토큰 추정치, 실행 환경 식별 정보는 빠져 있다. 금액 산출 기준도 없다.
- GitHub CLI가 로그인되지 않아 `gh run list`로 원격 Actions 결과를 읽을 수 없었다. CI workflow는 저장소에 존재한다.

## 설계

### 1. 답변 근거와 PageRank 관련 논문 분리

- `evidence_ids`는 답변 본문이 직접 뒷받침하는 논문 ID만 담는다.
- 시스템 프롬프트는 관련 논문을 답변 문자열 안에 ID와 함께 나열하지 말고, 도구 결과를 UI가 별도 표로 보여 준다는 점을 명시한다.
- `validate_answer`는 직접 도구 결과(`papers`, `rows`)에 없는 ID를 거부한다. `related`만으로 얻은 ID를 주 답변 근거로 받아들이지 않는다.
- 앱의 기존 PageRank 관련 논문 표와 그래프 표시 동작은 유지한다.
- 평가 보고서는 `answer_evidence_precision/recall`과 관련 논문 검색 지표를 구분한다. curated 케이스에 `expected_related_ids`가 있을 때만 관련 논문 hit/precision/recall을 계산하고, gold 목록이 없으면 `null`로 둔다. 기존 `citation_precision/recall` 필드는 호환성을 위해 유지하거나 명시적 버전 전환을 둔다.

### 2. 토픽 평가셋 보강

- 기존 31건 자동 스냅샷은 변경하지 않고 그대로 보존한다.
- 별도 curated 후보셋에 10개 이상의 토픽 질문, 제한된 gold arXiv ID 집합, 정답에 필요한 사실 문구, 출처 논문·abstract 내 근거 발췌, 라벨 작성 근거를 기록한다.
- 각 레코드는 `review_status: pending_human_review`로 표시한다. 사람의 확인 기록이 없는 후보를 사람이 검토한 정답셋 또는 공식 점수로 표현하지 않는다.
- 평가 실행기는 기존 필드가 없는 레거시 케이스와 새 provenance 필드를 모두 읽는다.

### 3. 토큰·비용·지연시간 계측

- provider 응답 메타데이터에서 채팅 입력·출력 토큰을 읽고, 메타데이터 누락은 `null`로 기록한다.
- 임베딩 질의 텍스트 토큰은 임베딩 모델과 호환되는 `tiktoken` 인코딩으로 세며, 보고서에서 측정이 아닌 tokenizer 기반 추정임을 표시한다.
- 케이스별 end-to-end 경과시간을 유지하고 요약에 평균, p50, p95를 기록한다.
- 다음 선택 환경값이 모두 유효할 때만 API 금액 추정치를 계산한다: `EVAL_CHAT_INPUT_USD_PER_1M`, `EVAL_CHAT_OUTPUT_USD_PER_1M`, `EVAL_EMBEDDING_USD_PER_1M`. 단가는 USD/1M tokens이며, 보고서에 단가와 `EVAL_PRICING_SOURCE`를 기록한다.
- 단가가 하나라도 없거나 채팅 토큰·임베딩 사용량이 불완전하면 금액은 `null`이다. Neo4j/Aura 비용은 계측 범위에서 제외한다고 명시한다. 단가를 하드코딩하거나 임의 추정하지 않는다.

### 4. 실험 재현 메타데이터

각 보고서에 실행 시각(UTC), 모드, top-k, 사용한 케이스 ID, 데이터셋 SHA-256, 앱 모델·임베딩 모델, Python 및 주요 패키지 버전, OS/platform, Git commit SHA와 dirty 상태를 기록한다. `.env` 값, API 키, 데이터베이스 비밀번호, URI 전체는 기록하지 않는다.

### 5. 검증

- 인용 검증·검색 결과 출처·평가셋 스키마·p50/p95·토큰 누락·가격 누락/계산·재현 메타데이터에 대한 결정론적 단위 테스트를 추가한다.
- Neo4j/OpenAI 연결 없는 CI 테스트, Ruff, Python 컴파일, 잠금 파일 검사를 통과시킨다.
- 인증 정보가 있는 경우 GitHub Actions 최근 실행을 읽어 상태를 확인한다. 인증이 없으면 로컬 동일 검증을 수행하고 원격 CI 결과는 확인되지 않았다고 보고한다. 이 설계는 자동 push를 포함하지 않는다.

## 성공 조건

1. Related papers에만 나온 ID가 `evidence_ids`에 섞이지 않으며, 관련 논문 평가는 별도 지표에 기록된다.
2. 새 토픽 후보 평가셋이 출처·사실 문구·검토 상태를 포함하고, 사람 검토 전 상태가 명확하다.
3. 비교 JSON에 p50/p95, 채팅 및 임베딩 토큰, 설정 단가가 있을 때 계산된 비용 또는 명확한 `null` 사유가 들어간다.
4. 실행 모델·데이터셋·환경·Git 상태가 보고서에 남으며 민감정보는 포함되지 않는다.
5. 로컬 검증 전체가 통과한다. 원격 CI는 관측 가능한 근거만 보고한다.

## 범위 밖

- Neo4j 요금을 임의 추정하거나 과금 API를 추가하지 않는다.
- 원본 그래프/임베딩 데이터, `.env`, 백업 저장소는 수정하지 않는다.
- 사람 검토가 완료되지 않은 후보 라벨로 품질 향상을 주장하지 않는다.
- 변경사항을 원격 브랜치에 push하지 않는다.
