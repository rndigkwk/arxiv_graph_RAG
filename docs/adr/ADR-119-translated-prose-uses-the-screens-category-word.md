# ADR-119: 옮긴 문단의 분류 용어를 화면 용어로 맞춘다 — 지시문은 바꾸지 않는다

- **상태:** 채택
- **날짜:** 2026-11-09

## 맥락

[ADR-117](ADR-117-known-table-headers-are-translated-without-the-model.md)로 표 머리줄은 늘 "주 분류"가 되었습니다. 그런데 같은 답의
문단은 모델이 옮기므로, 같은 "primary category"가 다른 말이 됩니다.

- 11-09 운영 화면에서 머리줄은 "주 분류", 바로 위 문단은 "주 카테고리"였습니다(ADR-117 머지 뒤 VM 확인).
- 저장된 답 6개를 로컬에서 옮겨 보니 "주 카테고리", "기본 카테고리", 그냥 "카테고리"가 섞여 나왔습니다. 앞선 측정(ADR-112)에서는
  "1차 카테고리"도 있었습니다.

화면은 이 말을 "분류"로 씁니다(머리줄, 노드 이름 "분류 안에서 찾기").

## 결정

- **모델이 옮긴 한국어에 `table_passthrough.korean_terms`를 씌웁니다.**
  - "주 / 기본 / 1차 / 일차 카테고리"(띄어쓰기 있든 없든)는 "주 분류"로 바꿉니다.
  - 남은 "카테고리"는 "분류"로 바꿉니다.
  - 두 말 모두 모음으로 끝나 뒤의 조사(가·를·는·와·로)가 그대로 맞습니다.
- 흘려 보내는 조각에도 같은 것을 씌웁니다. 화면이 끝에 가서 말이 바뀌는 것을 보지 않습니다.
- 영어(제목의 "Category Theory" 등)는 건드리지 않습니다.
- 번역 지시문은 바꾸지 않습니다.

## 측정

로컬에서 VM과 같은 번역기로 저장된 답 3개를 옮겼습니다. 바꾸기 전에는 "카테고리" / "기본 카테고리" / "주 카테고리"였고,
바꾼 뒤에는 모두 "분류" / "주 분류"였습니다. 문자열 치환이라 지연은 늘지 않습니다.

## 고르지 않은 것

- **번역 지시문에 용어집을 넣기.** 모든 번역이 그만큼 더 읽고, 모델이 따르는지는 실행마다 다릅니다(ADR-117과 같은 이유).
- **"분류"를 "카테고리"로 맞추기.** 화면 문구와 노드 이름이 이미 "분류"입니다.

## 민감도

- **다른 뜻의 "카테고리"도 "분류"가 됩니다.** 이 앱의 답에서 "카테고리"는 arXiv 분류를 뜻합니다. 다른 뜻이 보이면 바꾸는 범위를 좁힙니다.
- **`src/`가 바뀌어 머지하면 VM API가 다시 뜹니다**([ADR-107](ADR-107-restart-the-api-only-when-it-reads-the-change.md)).
