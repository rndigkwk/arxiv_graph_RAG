# ADR-091: 답 쓰는 에이전트도 추론을 끄고 부른다 — 턴은 빨라지고, 그만큼 판정이 앞에 선다

- **상태:** 채택
- **날짜:** 2026-10-28

## 맥락

판정의 추론을 끈 뒤([ADR-089](ADR-089-judge-without-reasoning.md)) 남은 대기 중 가장 큰 것은 `generate`입니다(CI p50
약 5초, 평균 2턴). 에이전트도 앱의 `llm`(gpt-6-luna, 기본 추론 강도)을 그대로 씁니다. 판정과 같은 방법 - 모델·지시문·
도구·구조화 응답은 그대로 두고 추론 강도 하나만 바꾸기 - 을 에이전트에 써 봅니다.

미리 알고 있던 제약이 하나 있습니다. 판정은 마지막 턴이 근거 ID를 내는 순간 시작해 답 글과 겹칩니다
([ADR-085](ADR-085-overlap-the-condition-check-with-the-answer.md)). 그래서 **마지막 턴이 빨라지면 판정을 기다리는 시간이
그만큼 늘어날 수 있습니다.** 끝까지의 이득은 판정 시작 전의 턴에서만 확실히 나옵니다.

## 먼저 잰 것 — 로컬, 같은 질문에 강도 셋을 번갈아

`scripts/probe_agent_effort.py`는 `chatbot.agent`를 같은 도구·지시문·`GroundedAnswer`로 다시 만들고 모델 복사본의
`reasoning`만 다르게 둡니다. 가족마다 2문항과 "최근" 질문 2개, 질문마다 강도 순서를 돌렸습니다(로컬 Aura).

| 강도 | 턴당 p50 | 전체 p50 | 정답 적중 | 근거 정밀도 < 1 | 재시도 | 기권 |
|---|---:|---:|---:|---:|---:|---:|
| 앱 기본값 | 3.00초 | 7.60초 | 10/10 | 0 | 2 | 0 |
| `low` | 2.41초 | 6.20초 | 10/10 | 0 | 1 | **1** |
| `none` | **2.15초** | 6.93초 | 10/10 | 0 | **0** | 0 |

- 기본값의 재시도 두 번은 둘 다 "최근" 질문이었고 판정이 `mixed_candidate_conditions`로 돌려보냈습니다. `none`은 두
  질문 모두 한 번에 통과했습니다.
- `low`는 한 질문에서 기권했습니다. 그래서 `low`가 아니라 `none`을 봅니다.
- 로컬 벽시계는 실행마다 크게 흔들립니다. 전체 p50보다 턴당 시간과 재시도를 봅니다.

## 결정

**답 쓰는 에이전트를 `reasoning={"effort": "none"}`으로 부릅니다**(`chatbot.agent_llm`, `AGENT_REASONING`). 판정과 같이
`llm.model_copy`로 강도 하나만 바꾸고, 원본 `llm`은 그대로라 논문 비교(`compare_papers`)는 기본 강도입니다. 평가
보고서의 메타데이터에 `agent_reasoning`·`judge_reasoning`을 적어, 어느 강도가 답했는지 보고서만 보고 알 수 있게 합니다.

## 결과 — CI full 평가, main과 같은 시각에 짝으로 3회

CI의 `concurrency`가 같은 브랜치 실행을 취소하므로 임시 브랜치(`tmp-eval-main-1..3`, `tmp-eval-agent-1..3`)로 main
(09e3d2e)과 이 브랜치(4179be4)를 번갈아 동시에 돌렸습니다. 실행 40626532568·40626538085·40626543514(main),
40626535424·40626540484·40626546930(이 브랜치). 여섯 번 모두 성공이고 게이트를 통과했습니다. 지시문이 바뀌지 않았으므로
기준선은 다시 쓰지 않습니다.

| p50 | main 3회 | `none` 3회 |
|---|---:|---:|
| 턴당 시간 | 2.34 · 2.26 · 2.29초 | **1.72 · 1.82 · 1.85초** |
| `generate` | 5.11 · 5.03 · 5.04초 | **3.89 · 4.04 · 4.14초** |
| 마지막 턴 | 2.53 · 2.53 · 2.45초 | 1.88 · 1.97 · 2.03초 |
| `check_conditions`(판정 대기) | 2.96 · 2.22 · 2.93초 | 3.30 · 4.54 · 3.65초 |
| 그래프 전체 | 8.84 · 8.79 · 9.16초 | 7.69 · 9.44 · 9.57초 |
| 그래프 전체 p90 | 16.78 · 16.31 · 15.83초 | 18.20 · 20.33 · 16.53초 |
| 평균 모델 턴 | 2.07 · 2.07 · 2.00 | 2.03 · 2.00 · 2.03 |

실행 단위 p50은 섞여 보입니다. 그래서 **같은 문항끼리** 견줍니다(문항마다 세 번의 평균, `none` − main, 30문항).

| 구간 | 차이 중앙값 | 차이 평균 | `none`이 빠른 문항 |
|---|---:|---:|---:|
| 판정 시작 전(`generate` − 마지막 턴) | −0.45초 | −0.59초 | **26/30** |
| 마지막 턴 | −0.57초 | −0.67초 | **30/30** |
| 판정 대기 | +0.48초 | +1.00초 | 7/30 |
| 마지막 턴 + 판정 대기 | −0.07초 | +0.33초 | 16/30 |
| 그래프 전체 | **−0.59초** | −0.25초 | 21/30 |

**턴은 모든 문항에서 빨라졌고, 마지막 턴이 줄어든 만큼 판정 대기가 늘었습니다.** 판정이 겹친 채 끝나지 않고 답 글보다
늦게 끝나는 것입니다 - 이제 판정이 끝까지의 경로 위에 있습니다. 끝까지의 이득은 판정 시작 전의 턴에서 나온 0.45초
안팎이고, 전체 중앙값 −0.59초와 맞습니다.

품질은 그대로입니다.

- 근거 정밀도·재현율·적중은 여섯 번 모두 1.0, 실패 0, 재시도 0입니다.
- `ragas_faithfulness`는 main 0.9889 ×3, `none` 0.9917 · 1.0000 · 1.0000입니다.
- `ragas_answer_relevancy`는 main 0.8385 · 0.8546 · 0.8402, `none` 0.8608 · 0.8491 · 0.8549입니다.
- 메타데이터의 `agent_reasoning`은 `{"effort": "none"}`으로 적혔습니다.

## 민감도

- **이득이 작고, p90은 나빠졌을 수 있습니다.** 실행 단위 p90은 세 번 모두 main보다 컸습니다(문항 30개의 p90은 세
  문항이 정합니다). 그래도 채택하는 것은 판정 시작 전의 턴이 26/30에서 빨라졌고 품질이 그대로였기 때문입니다. VM에서
  p90이 main보다 나쁘면 다시 봅니다.
- **다음 자리는 판정 자체입니다.** 판정이 이제 경로 위에 있으므로, 에이전트를 더 줄여도 끝까지는 덜 줄어듭니다. 판정
  호출을 줄이는 것(입력 길이, 판정 시작 시점)이 다음입니다.
- **게이트는 에이전트의 추론 강도를 보지 않습니다.** 프롬프트 지문이 같기 때문입니다([ADR-041](ADR-041-the-gate-reads-the-prompt.md)).
  그래서 보고서 메타데이터에 강도를 적고, `tests/test_agent_reasoning.py`가 에이전트가 복사본으로 만들어지는지 봅니다.
- 근거·검색 지표가 기준선 아래로 내려가거나 기권·재시도가 늘면 뒤집습니다.
