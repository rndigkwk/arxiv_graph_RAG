# ADR-005: Aura Free 계정 추가로 용량을 늘리지 않는다

- **상태:** 기각
- **날짜:** 2026-10-13

## 맥락

관계가 한도의 84.6%라 용량이 빡빡합니다. 무료 계정 2개로 나누면 한도가 두 배가 됩니다.

## 결정

하지 않습니다.

## 근거

**조용히 틀린 답이 나오는 것이 결정적입니다.** 에이전트는 Cypher 하나를 씁니다. "이 저자가 인용한
논문"에서 저자가 A샤드, 피인용 논문이 B샤드에 있으면 **에러가 아니라 빈 결과**가 돌아옵니다.
근거 검증이 핵심인 프로젝트에서 최악의 실패 양식입니다.

| 문제 | 내용 |
|---|---|
| 샤드 간 조인 불가 | Free는 인스턴스당 DB 1개, Composite database는 상위 등급 |
| 인용망이 쪼개지지 않음 | 37,854편에 69,438 간선. 커뮤니티 간 흐름만 C1↔C2 963+561건 |
| `top_k` 의미 붕괴 | "유사도 상위 5편"이 "각 샤드 상위 5편 중 5편"이 됨 |
| 일시정지 2배 | "A는 깨어 있고 B는 잠든" 부분 실패를 앱이 처리해야 함 |
| 포트폴리오 손해 | 무료 한도 회피용 다중 계정. 제약 아래 설계했다는 강점이 사라짐 |

**그리고 로드맵이 추가 용량을 쓰지 않습니다.** 계획된 작업 전부가 현재 용량 안에서 됩니다.

## 용량이 정말 필요해지면

순서가 정해져 있습니다. ① 저자 데이터 정리(진짜 레버) → ② 실험용은 Docker 로컬 Neo4j →
③ 자체 호스팅. 샤딩은 어느 단계에도 없습니다.

## 민감도

**로드맵이 바뀌면 재검토 대상입니다.** 다만 그때도 샤딩이 아니라 자체 호스팅이 먼저입니다
(`ROADMAP.md` 8-2-1절: 더 싸고 더 강함).
