# ADR-111: 답을 한국어로 옮길 때 표의 행은 보내지 않는다 — 머리줄과 설명 열은 옮긴다

- **상태:** 채택
- **날짜:** 2026-11-07

## 맥락

[ADR-108](ADR-108-the-question-screen-shows-the-answer-first.md)의 화면은 한국어 질문에 대한 영어 답을
`/api/translate`로 옮깁니다. 2026-11-07 측정(`reports/vm_answer_latency_examples.json`)에서 번역은 p50
2.52초였지만, "Attention Is All You Need를 인용한 논문을 알려 줘"처럼 25행 표가 든 답은 7초까지 걸렸습니다.
한국어 답이 뜨기까지 p50 12.12초 가운데 번역이 가장 큰 단일 몫이었습니다.

그 표의 행은 arXiv ID, 제목, 분류 코드, 인용 수뿐입니다. 번역 지시문(`TRANSLATE_TO_KOREAN`)은 이것들을
영어로 두라고 합니다. 그런데도 모델은 출력 토큰으로 한 글자씩 다시 써야 했습니다. 나가는 글자가 같아도
시간이 듭니다.

## 결정

**영어로 남을 표 행은 번역에 보내지 않고, 자리표시 `[[TABLE_n]]`로 바꿔 두었다가 돌아온 번역에 그대로
끼웁니다**(`src/table_passthrough.py`, `chatbot.translate_to_korean`).

- **머리줄과 구분선은 보냅니다.** 예전 번역은 "Title"을 "제목", "Citations"를 "인용 수"로 옮겼습니다.
  그 모습은 그대로 둡니다. 모델이 머리줄과 자리표시 사이에 빈 줄을 넣으면 표가 끊기므로, 되돌릴 때 그 빈
  줄을 지웁니다.
- **설명 문장이 든 표는 통째로 보냅니다.** 마침표로 끝나고 네 단어 이상인 칸이 하나라도 있으면 설명
  열로 봅니다. "How they use graph neural networks" 같은 열은 읽는 사람에게 옮겨야 합니다. 제목 칸은
  마침표로 끝나지 않습니다.
- **자리표시가 하나라도 빠지거나 늘면** 예전처럼 원문 전체를 한 번 더 번역합니다. 표를 잃느니 느린 편이
  낫습니다.
- **옮길 문장이 없는 답**(머리줄을 빼면 표뿐)은 모델을 부르지 않고 원문을 돌려줍니다.
- 번역 지시문, 판정, 화면은 바꾸지 않습니다. `/api/translate`의 입력과 출력 모양도 같습니다.

## 측정

VM에서 화면 예시 3문항의 답을 받고(2026-11-07), 같은 답을 로컬에서 예전 방식(전체 번역)과 새 방식으로
번갈아 4번씩 옮겼습니다. 순서는 라운드마다 바꿨습니다(`reports/translate_table_rows_pair.json`).

| 답 | 건너뛴 행 | 예전 p50 | 새 p50 |
| --- | ---: | ---: | ---: |
| Attention 인용 논문(2,915자, 3열 표) | 25 | 6.60초 | 2.60초 |
| cs.AI 피인용 상위 5편(590자, 4열 표) | 5 | 2.42초 | 2.22초 |
| GNN 지식 그래프 추론(562자, 설명 열 있는 표) | 0 | 2.23초 | 2.41초 |

셋째 답은 두 방식이 같은 길을 탑니다. 차이는 잡음입니다. 설명 열을 가리기 전의 구현으로 따로 잰 9번에서
자리표시가 깨져 전체 번역으로 돌아간 일은 없었습니다. 이번 8번(표를 건너뛴 두 답 × 4)에서도 건너뛴 행은
글자 하나 다르지 않게 돌아왔습니다. 셋째 답의 설명 열은 예전 번역이 한국어로 옮겼기 때문에 행을 건너뛰지
않는 규칙을 더했습니다.

**로컬에서 잰 수치입니다.** VM은 같은 OpenAI 모델을 부르지만 네트워크가 다릅니다. 머지 뒤
`measure_vm_answer_latency.py --examples`로 한국어 답이 뜨기까지를 다시 재서
[EVALUATION.md](../EVALUATION.md)에 적습니다.

## 고르지 않은 것

- **번역 지시문에 "표는 건드리지 말라"를 더하기.** 지시문은 이미 그렇게 말합니다. 모델이 따르더라도 그
  행을 출력해야 하므로 시간이 줄지 않습니다.
- **화면(web)에서 표를 떼어 보내기.** 번역 API를 부르는 곳은 화면과 측정 스크립트 둘입니다. 서버에서 하면
  둘 다 같은 답을 받습니다.
- **표를 통째로 빼기(머리줄까지).** 처음 구현이 그랬습니다. 머리줄이 영어로 남아 예전보다 덜 옮긴 화면이
  되어 머리줄은 보내도록 바꿨습니다.
- **열 이름으로 설명 열을 가리기.** 모델이 열 이름을 질문마다 다르게 씁니다("How they use…", "Summary").
  칸의 모양(문장인가)으로 봅니다.

## 민감도

- **마침표 없는 짧은 설명 칸**("joint reasoning with KG")은 문장으로 보지 않아 영어로 남습니다. 지시문은
  표를 "Title | … | Primary category" 열로 쓰라고 하므로 드뭅니다. 틀리면 덜 옮기는 쪽입니다.
- **마침표로 끝나는 긴 제목**이 있으면 그 표는 예전처럼 통째로 번역됩니다. 틀리면 느린 쪽입니다.
- **최악의 경우 번역을 두 번 부릅니다**(자리표시가 깨졌을 때). 측정에서는 일어나지 않았습니다.
- **`src/`가 바뀌어 머지하면 VM API가 다시 뜹니다**([ADR-107](ADR-107-restart-the-api-only-when-it-reads-the-change.md)).
