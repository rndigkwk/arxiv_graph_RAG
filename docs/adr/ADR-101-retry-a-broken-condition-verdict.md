# ADR-101: 깨진 조건 판정은 답을 고치게 하지 않고 판정을 다시 부른다 — 판정 출력에는 상한을 둔다

- **상태:** 채택
- **날짜:** 2026-11-05

## 맥락

2026-11-02 정기 회귀 평가가 두 번 실패했습니다(이슈 #109). 깨진 문항은 실행마다 달랐고, 둘 다 "X를 인용한 논문" 질문입니다.

| 실행 | 문항 | 근거 재현율 | 조건 판정 시간 |
|---|---|---|---:|
| 전체 30문항 | `citing-03` | 1.0 → 0.5 | 1.63초 |
| 바꿔 말한 60문항 | `citing-06-p1` | 1.0 → 0.0 | 1,442초 |

두 실행의 결과물을 열어 보니, 실패한 경로가 같았습니다.

1. 첫 답은 정답 논문을 인용했습니다.
2. 조건 판정 호출이 **논문마다 하나씩 판정을 돌려주지 못했습니다**(`incomplete_content_verdict`). 두 실행에서 이 이유가
   모두 세 번 나왔고, 다른 이유의 거절은 0번이었습니다.
3. 그러자 그래프가 답을 되돌리며 수정 요청을 보냈습니다. 요청은 "주제 조건과 그래프 조건을 둘 다 확인하고, 하나라도
   어긋나는 논문은 빼라"였습니다.
4. 에이전트는 질문에 없던 주제 조건을 지어냈습니다. `citing-03`은 "긴 상호작용 평가" 주제를 붙여 정답 두 편 중 한 편을
   뺐습니다. `citing-06-p1`은 "둘 다 주제 조건을 만족하는지 확인할 수 없다"며 한 편도 남기지 않았습니다.
5. 두 번째 판정은 둘 다 정상으로 돌아왔습니다.

판정이 깨진 것은 답의 잘못이 아닙니다. 그런데 지금 구조는 그것을 답의 잘못으로 처리합니다. 판정을 다시 부르면 되는 일을,
답을 다시 쓰게 만들어 정답을 잃었습니다.

`citing-06-p1`의 판정은 한 번에 출력 128,424토큰과 1,442초를 썼습니다. 정기 평가 90문항에서 답과 판정을 합친 문항당 출력은
그 문항 말고는 최대 1,085토큰입니다. 판정은 흘려 받으므로, `timeout=60`은 조각이 계속 오는 동안 끊지 않습니다.

## 결정

- **판정이 읽을 수 없거나 논문 수가 맞지 않으면, 판정만 한 번 더 부릅니다**(`candidate_validation.JUDGE_ATTEMPTS = 2`).
  두 번 다 깨질 때만 지금처럼 답을 되돌립니다. 제한 시간·연결 같은 다른 예외는 다시 부르지 않습니다. 다시 불러도
  기다림만 두 배가 되기 때문입니다.
- **판정 한 번의 출력은 4,000토큰까지로 막습니다**(`chatbot.JUDGE_MAX_TOKENS`). 위에서 본 문항당 최대의 약 4배입니다.
  상한에서 잘린 판정은 읽을 수 없으므로, 위의 재시도로 이어집니다. 답 쓰는 에이전트와 논문 비교에는 상한을 두지 않습니다.

비용은 판정이 깨질 때만 듭니다. 위의 실행에서는 90문항 중 세 번, 판정 한 번(p50 1.57초, ADR-089)만큼입니다.

## 고르지 않은 것

- **수정 요청 문구를 고치기.** "질문에 없는 조건은 만들지 마라"를 넣는 방식입니다. 이렇게 해도 답을 다시 쓰는 비용은
  그대로 남습니다. 그리고 지시문을 늘리면 모든 턴이 느려집니다. 원인은 판정 쪽에 있으므로 판정 쪽에서 고칩니다.
- **판정을 흘려 받지 않게 바꾸기.** 그러면 `timeout=60`이 전체 시간에 걸립니다. 하지만 60초 동안 토큰을 계속 쓰는 것은
  막지 못합니다. 출력 상한이 시간과 비용을 함께 막습니다.

## 민감도

- 단위 테스트로 확인한 것은 재시도 경로입니다. 깨진 판정이 다시 불렀을 때 성공하는지는 11-02의 두 번째 판정 두 건이
  보여 준 것뿐입니다. 다음 정기 평가에서 `incomplete_content_verdict`가 다시 나오면, 거절 대신 재시도가 찍히는지 확인합니다.
- 판정이 왜 깨지는지(추론을 끈 구조화 출력의 반복 출력으로 보입니다)는 원문을 남기지 않아 재지 못했습니다.
