# ADR-127: 회귀 평가가 프롬프트 캐시 비율을 적고, 크게 떨어지면 경고한다 — 판정은 바꾸지 않는다

- **상태:** 채택
- **날짜:** 2026-11-11

## 맥락

에이전트는 질문마다 지시문과 도구 설명을 다시 보냅니다. 앞부분이 같아서 OpenAI 프롬프트 캐시가 그것을 할인합니다.
압축을 넣지 않은 이유도 입력 대부분이 이미 캐시에서 읽힌다는 것이었습니다([ADR-025](ADR-025-reject-context-compression.md)).
지시문을 앞에, 질문마다 다른 것을 뒤의 턴 메시지로 붙이는 배치도 그것을 지키려는 것입니다(ADR-087·088·090).

그런데 **주간 회귀 평가 보고서에는 캐시 읽기가 없었습니다.** 캐시를 적는 것은 `--mode agent`뿐이고,
게이트가 돌리는 `--mode compare`는 적지 않습니다. 11-09 정기 실행 두 개(`full`, `paraphrase`)의 보고서를 받아 확인했습니다.
그래서 지시문 앞부분에 질문마다 달라지는 값(날짜, 사용자 언어 등)을 넣는 변경이 들어와도 **품질은 같고 비용만 늘어** 아무 데도 보이지 않습니다.
교안(Day 79)의 접두어 캐시 적중 비율과 같은 신호입니다.

## 측정

캐시를 적은 보고서 두 개에서 쟀습니다(에이전트 입력 기준).

| 보고서 | 사례 | 실행 전체 비율 | 사례 최저 |
|---|---|---|---|
| `reports/routing_after_rest.json` (10-18) | 18 | 0.858 | 0.828 |
| `reports/inside_generate_2026-10-26.json` (10-26) | 30 | 0.885 | 0.467 (`author-01`, 입력 5,689) |

사례 하나의 비율은 입력이 짧으면 크게 흔들립니다. 실행 전체로 보면 0.86~0.89입니다.

## 결정

- **`--mode compare`도 에이전트 입력과 그중 캐시 읽기를 적습니다**(`chat_input_tokens_agent`, `chat_input_tokens_cached`).
  분모는 에이전트 입력만입니다. 조건 판정 호출은 에이전트의 접두사를 쓰지 않으므로, 넣으면 판정 길이에 따라 비율이 흔들립니다.
- **게이트가 실행 전체의 합으로 비율을 냅니다**(`evals.gate.cache_read_ratio`). 여러 실행을 합칠 때도 더합니다. 사례 평균이 아닙니다.
- **기준은 0.5입니다**(`CACHE_READ_ALARM`). 잰 실행 전체 비율보다 0.35 이상 아래이고, 앞부분이 깨지면 비율은 0 근처로 떨어지므로 그 사이입니다.
- 요약(`reports/summary.md`)에 비율을 늘 한 줄 적고, 기준 아래면 절을 하나 더하고 Actions에 `::warning`을 띄웁니다.
  **판정은 바꾸지 않습니다.** [ADR-116](ADR-116-warn-on-a-long-output-per-case.md)의 출력 길이 경고와 같은 선입니다.
- 캐시를 적기 전의 보고서는 비율을 지어내지 않습니다(`None`, 요약에 줄 없음).

## 고르지 않은 것

- **실패로 막기.** 캐시는 공급자가 정하므로(최소 길이, 보존 시간) 우리 변경 없이도 떨어질 수 있습니다. 몇 주 값을 본 뒤에 정합니다.
- **기준선과 비교하는 지표로 넣기.** 품질 지표가 아니라 비용 신호이고, 기준선 하한은 손으로 정하는 값이라 같은 칸에 두지 않습니다.
- **운영 트래픽의 비율로 알리기.** ADR-126(PR #158)의 SLI 줄에도 캐시 읽기가 있지만, 하루 수십 건이고 질문이 매번 다릅니다. 평가는 같은 질문을 매주 돌리므로 비교가 됩니다.

## 민감도

- **측정이 두 보고서, 48건뿐입니다.** 지금 프롬프트로 잰 값이 아닙니다. 첫 몇 주의 정기 실행 비율이 0.86~0.89 밖이면 기준을 다시 봅니다.
- **OpenAI가 캐시 규칙을 바꾸면**(최소 1,024토큰, 보존 시간) 우리 변경 없이 경고가 뜰 수 있습니다. 그때는 경고가 맞게 뜬 것입니다. 비용이 실제로 늘었습니다.
- 질문 하나의 입력이 1,024토큰 아래로 짧아지면 그 질문은 캐시되지 않습니다. 실행 전체의 합이라 크게 움직이지 않습니다.
