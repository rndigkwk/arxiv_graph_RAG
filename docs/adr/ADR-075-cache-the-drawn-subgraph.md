# ADR-075: 그린 부분 그래프를 캐시한다 — 다시 그릴 때마다 답변 수만큼 조회하고 있었다

- **상태:** 채택
- **날짜:** 2026-10-26

## 맥락

Streamlit은 버튼 하나를 눌러도 스크립트를 처음부터 다시 돌리고, 챗봇 탭은 대화 기록의 답변을
**전부** 다시 그렸습니다. 답변마다 `chatbot.fetch_subgraph`가 Aura에 질의 두 개(논문 행, 인용
간선)를 보냅니다.

2026-10-26에 저장된 기준선 답변 10개의 논문 묶음(2~8편)으로 30번 불러 쟀습니다(읽기 전용, 0원).
**중앙값 0.40초, 최대 0.50초**입니다. 답변이 다섯 개면 번역 버튼 하나에 약 2초가 그래프 조회로
갑니다. 같은 묶음을 같은 답변에서 다시 읽는 것이므로 결과는 매번 같습니다.

이 측정은 일회성 스크립트로 했고 보고서로 남기지 않았습니다. 결정이 수의 크기에 기대지 않기
때문입니다 — 같은 값을 다시 읽는 비용은 0이 아니기만 하면 됩니다.

## 결정

- `app.py`의 `subgraph_of(ids)`가 `st.cache_data(ttl=6시간, max_entries=256)`로 감쌉니다. 열쇠는
  논문 ID 튜플입니다. 답변 화면과 PageRank 탭의 그래프, 두 자리가 모두 이것을 거칩니다.
- **6시간인 이유:** 그래프는 주간 수집 때만 바뀝니다. 하루보다 짧게 두어 수집 뒤 하루 안에는 새
  간선이 그림에 나옵니다.
- **실패는 캐시하지 않습니다.** `st.cache_data`는 예외를 저장하지 않으므로 Aura가 잠깐 멈춘 뒤에도
  다음 그리기에서 다시 묻습니다.

같은 날 [ADR-076](ADR-076-the-latest-answer-is-a-workbench.md)이 지난 답변을 접으면서 지난 답변은
아예 그래프를 읽지 않게 됐습니다. 이 캐시는 작업대에 펼친 답변과, 새 답변 뒤 한 번 더 그리는 자리를
받습니다.

## 민감도

- **열쇠는 순서까지 봅니다.** 같은 논문을 다른 순서로 넘기면 다시 읽습니다. 한 답변의 순서는 바뀌지
  않으므로 실제로 일어나지 않는 경우입니다.
- **메모리:** 한 항목은 논문 15편 이하의 행과 간선입니다. 256개를 다 채워도 앱 피크(약 260MB)에 비해
  작다고 보지만 재지 않았습니다.
- **수집 직후 6시간 동안 그림이 옛것일 수 있습니다.** 답변 본문과 근거는 캐시하지 않으므로 그림만
  늦습니다.
