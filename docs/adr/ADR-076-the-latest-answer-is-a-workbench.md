# ADR-076: 최신 답변은 세 칸 작업대로, 지난 답변은 접는다 — 접은 패널도 안쪽은 실행된다

- **상태:** 채택
- **날짜:** 2026-10-26

## 맥락

챗봇 탭은 답변 하나를 한 칸에 세로로 쌓았습니다. 도구 표시 → 답변 → 그래프 → 접힌 패널 넷이고,
답을 읽은 뒤 근거(인용 ID·Cypher)를 보려면 스크롤이 길었습니다. 2026-10-24의 프론트 시안이 이것을
"연구용 작업대"로 다시 배치했습니다 — 왼쪽 경로, 가운데 답변, 오른쪽 근거.

시안을 그대로 옮기면 하나가 나빠집니다. 이 앱은 **다시 그릴 때마다 대화 기록 전체를 다시
그립니다.** 답변마다 세 칸을 그리면 스크롤이 더 길어지고, 답변마다 그래프 조회와 인용 경로 조회가
반복됩니다. 그래서 그날 "최신 답변만 작업대로, 과거는 접기"를 권했고 결정은 미뤄졌습니다.

## 결정

1. **작업대는 하나입니다.** 기본은 가장 최근 답변이고, 지난 답변의 "작업대에 펼치기"를 누르면 그
   답변이 작업대로 옵니다. 새 답변이 오거나 대화를 지우면 최근 답변으로 돌아갑니다. 고른 위치가
   답변이 아니면(지운 대화의 위치 등) 최근 답변으로 떨어집니다.
2. **세 칸:** 왼쪽 *이 답변의 경로*(도구 선택·지연 합계·검색어 번역, 접힌 단계별 소요 시간),
   가운데 *답변*(본문·번역 버튼·그래프·관련 논문·예측·초록·비교), 오른쪽 *근거*(인용 ID, **접지
   않은 Cypher**와 결과 행, 접힌 도구 요청 순서·그린 논문). 너비는 1 : 2.2 : 1.4이고 좁은 화면에서는
   Streamlit이 세로로 쌓습니다.
3. **지난 답변은 접고, 안쪽을 가볍게 둡니다.** Streamlit의 접힌 패널은 **안쪽도 실행합니다** —
   접기만 해서는 조회가 그대로 돕니다. 그래서 안쪽에는 답변 본문과 번역 버튼만 둡니다. DB에 닿는
   것이 없습니다.
4. **새 답변을 기록에 넣은 뒤 한 번 다시 그립니다.** 그렇지 않으면 그 실행에서는 앞 답변과 새 답변이
   둘 다 세 칸으로 남습니다. 로컬 화면에서 실제로 그렇게 보였습니다.
5. **그래프의 따로 떨어진 묶음을 3열 격자로 쌓습니다**(`packmode="array_3"`). 근거 논문들 사이에
   인용이 없으면 한 줄로 늘어서고, 가운데 칸 너비로 줄면 글자를 읽을 수 없었습니다.

## 시안에서 가져오지 않은 것

- **가족별 게이트 패널.** 질의 시점에는 질문의 가족을 모릅니다. 라우터가 정하는 것은 경로뿐이고,
  가족별 게이트는 [ADR-069](ADR-069-the-condition-check-keeps-its-quarter.md)에서 기각했습니다. 가족별
  요약도 6건이라 신뢰도를 띄울 수 없습니다.
- **인용되지 않은 벡터 결과를 그래프에서 빼기.** 지울 것은 논문이 아니라 "어떻게 들어왔는지 말하지
  않는 것"이었고, 테두리로 가르는 것으로 이미 바꿨습니다(ADR-065).
- BibTeX 복사·읽을 순서 같은 새 버튼은 이 결정의 범위가 아닙니다.

## 가정과 민감도

- **지난 답변의 근거를 보려면 한 번 눌러야 합니다.** 대화 중에 앞 답변의 Cypher를 자주 비교한다면
  이 배치가 불편합니다. 그 사용 빈도는 재지 않았습니다.
- **다시 그리기 한 번이 더 듭니다**(결정 4). 새 답변의 그래프는 캐시가 받으므로
  ([ADR-075](ADR-075-cache-the-drawn-subgraph.md)) 조회는 반복되지 않습니다.
- **`packmode`는 Streamlit이 브라우저에서 돌리는 Graphviz에 기댑니다.** 지원이 빠지면 예전처럼 한
  줄로 그려질 뿐 깨지지는 않습니다.

## 확인한 것 (2026-10-26)

로컬 앱에서 질문 둘을 던졌습니다. 첫 답변이 "지난 답변 — …"으로 접히고 작업대는 하나였습니다. 폰
너비(400px)에서는 세 칸이 세로로 쌓였습니다. 저자 질문의 논문 8편이 3열 격자로 그려져 칸 너비
449px에서 제목을 읽을 수 있었습니다.
