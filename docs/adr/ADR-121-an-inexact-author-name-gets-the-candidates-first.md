# ADR-121: 저자 이름이 딱 맞지 않으면 앱이 후보를 먼저 알려 준다 — 지시문은 바꾸지 않는다

- **상태:** 채택
- **날짜:** 2026-11-09

## 맥락

저자는 이름 문자열 하나가 노드 하나입니다(`prompts.AGENT_SYSTEM`의 스키마 설명). 11-09에 저자 질문을 물어 봤습니다.

| 질문 | 답 |
|---|---|
| "Bengio가 쓴 논문이 있어?" | **틀렸습니다.** "Emmanuel Bengio와 Samy Bengio의 논문이 있다"고 했고, 95편이 있는 Yoshua Bengio를 뺐습니다 |
| "Yang Liu가 쓴 논문" | "이 이름은 여러 사람일 수 있다"고 스스로 적었습니다 |
| "Yang Liu와 가장 많이 함께 쓴 공저자" | 주의 문구 없이 "Peng Li, 19편"이라고 했습니다 |

Bengio 답이 틀린 까닭은 모델이 쓴 Cypher입니다.

- 모델은 `toLower(a.name) CONTAINS "bengio"`로 찾고 이름순으로 정렬해 25행에서 끊었습니다.
- Emmanuel(4편)과 Samy(21편)만으로 25행이 다 찼습니다.

## 결정

- **`author` 노드를 둡니다**(`src/pre_author.py`, `chatbot.author_first`). 분류 노드 다음, 범위 노드 앞입니다.
- **저자를 묻는 질문에만 돕니다.**
  - 원문에 "쓴 / 썼 / 저자 / 공저 / 지은"이 있거나, 번역된 영어에 "wrote / written / authored / author / co-author / by"가 있어야 합니다.
  - 질문이 논문 하나를 지칭했으면(`resolve`) 건너뜁니다. 제목 낱말이 이름 후보로 잡히기 때문입니다.
- **이름 후보는 대문자로 시작하는 한~세 낱말입니다.** "Bengio", "LeCun", "Yoshua Bengio"가 해당합니다. 문장 첫머리 낱말("Are", "Papers")은 덜어 냅니다.
- **그래프에 딱 맞는 이름이 있으면 아무것도 하지 않습니다.** 대소문자는 가리지 않습니다. "Yoshua Bengio"와 "Yang Liu"는 메시지가 붙지 않습니다.
- **딱 맞는 이름이 없을 때만** 저자 이름 전문 색인(`arxiv_author_name_fulltext`)에서 그 낱말을 담은 저자를 찾습니다. 후보를 편수 순으로 다섯 명까지 이번 턴 메시지로 붙입니다.
  - 질문이 누구인지 고르지 않았으면, 편수가 가장 많은 사람을 `a.name =`으로 조회하게 합니다.
  - 나머지 사람은 메시지에 적힌 편수와 함께 답에서 언급하게 합니다.
  - CONTAINS는 쓰지 말라고 합니다.
- **도구 호출 기록에 `find_author`(by: app)로 남깁니다.** 논문 근거가 아니므로 `papers`에는 넣지 않습니다.
- **지시문과 도구 설명은 그대로입니다.**

## 측정

로컬(Aura)에서 물었습니다. Aura는 VM보다 작은 그래프라 편수가 다릅니다(Yoshua 87편, Samy 19편).

| 질문 | 바꾸기 전 | 바꾼 뒤 |
|---|---|---|
| "Bengio가 쓴 논문이 있어?" | Emmanuel과 Samy만 답함(1/1) | Yoshua Bengio의 논문을 보이고 Samy(19)·Emmanuel(4)을 편수와 함께 적음(3/3) |
| "LeCun이 쓴 논문 알려 줘" | - | Yann LeCun으로 찾음 |
| "Yoshua Bengio가 쓴 논문이 있어?" | 맞음 | 메시지 없음, 맞음 |
| "Yang Liu와 가장 많이 함께 쓴 공저자는?" | 주의 문구 없음 | 메시지 없음(딱 맞는 이름), 그대로 |

- 노드는 저자 질문에서 0.19~0.22초를 썼습니다(Aura). 저자를 묻지 않는 질문은 조회하지 않습니다.
- 첫 시도에서는 메시지가 "후보를 IN으로 함께 찾으라"고 했습니다. 그러자 모델이 이름순 25행을 다시 써서, Samy(19)와 Emmanuel(4)이 또 결과를 채웠습니다.
  그래서 편수가 가장 많은 사람 하나를 찾게 바꿨습니다.

## 고르지 않은 것

- **저자 이름 확인 도구(`resolve_author`)를 모델에 주기.** 도구 설명은 모든 질문의 턴이 읽습니다(ADR-090).
- **지시문에 "저자는 CONTAINS로 찾지 말라"를 넣기.** 위와 같은 이유입니다. 딱 맞지 않는 이름은 모델이 고칠 방법도 없습니다.
- **후보 전부를 함께 조회하게 하기.** 위 측정의 첫 시도입니다. 편수가 적은 사람이 행을 채웠습니다.

## 민감도

- **같은 이름의 다른 사람은 다루지 않습니다.** "Yang Liu" 한 노드에 231편이 분류 여덟 개에 걸쳐 있습니다.
  그래프만으로는 가를 수 없습니다. 강의 검토(🟢 3)대로 Semantic Scholar 저자 ID를 받을 때 다룹니다.
- **편수가 가장 많은 사람이 늘 묻는 사람은 아닙니다.** 다른 후보와 편수를 답에 적게 해서, 읽는 사람이 이어 물을 수 있게 합니다.
- **소문자로 쓴 이름("bengio")은 후보로 잡지 않습니다.** 지금처럼 모델이 찾습니다.
- **대문자로 시작하는 다른 낱말도 후보가 됩니다.** 그런 낱말이 저자 이름에 들어 있으면 메시지가 붙습니다. 메시지에는
  "이 저자에 대한 질문이 아니면 무시하라"가 있습니다.
- **회귀 평가(smoke)는 PR에서 돕니다.**
- **`src/`가 바뀌어 머지하면 VM API가 다시 뜹니다**([ADR-107](ADR-107-restart-the-api-only-when-it-reads-the-change.md)).
