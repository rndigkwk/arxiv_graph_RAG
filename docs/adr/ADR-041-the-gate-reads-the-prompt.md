# ADR-041: 게이트가 프롬프트를 읽는다 — 지문을 적어 두기만 하고 보지 않았습니다

- **상태:** 채택
- **날짜:** 2026-10-19

## 맥락

[ADR-018](ADR-018-prompt-versioning.md)이 프롬프트 본문의 단일 출처를 `prompts.py`로 정하고,
`sha256` 앞 12자를 평가 보고서의 `metadata.prompt_versions`에 적게 만들었습니다. 그 결정의
동기는 분명했습니다 — **프롬프트를 손으로 고치다 두 번 회귀를 냈고 둘 다 고친 뒤에 알았습니다**
(심판 정확도 21/21 → 11/21, ROADMAP 11-2).

그런데 다시 보니 **게이트가 그 칸을 읽지 않았습니다.**

| 점수를 움직이는 입력 | 게이트가 보는가 |
|---|---|
| 사례 집합 | 예 (`cases`) |
| RAGAS 판정 모델 | 예 (`judge_model`) |
| 사례 분할 | 예 (`metrics_split` 전제) |
| **프롬프트 본문** | **아니오** |

지문은 보고서에 **있었습니다.** 기준선을 만든 세 실행
(`reports/baseline_resolve_run{1,2,3}_setmetrics.json`)이 모두 적어 두었고 값도 서로 같습니다.
적어 두기만 하고 대조하지 않았으므로, 그 칸은 사고가 난 **뒤에** 읽을 기록이었을 뿐 사고를
막는 장치가 아니었습니다.

## 결정

**일곱 번째 규칙 `prompt_version`을 더합니다.**

```
| prompt_version | 답을 만든 프롬프트 본문이 기준선과 같은가 |
```

- 기준선에 `prompt_versions`를 적습니다. **다시 돌리지 않았습니다** — 세 실행의 지문이 서로
  같고 지금 `prompts.py`와도 같아서 그 값을 그대로 옮겼습니다. 지표는 한 자리도 바뀌지
  않습니다.
- `normalize()`가 보고서의 `metadata.prompt_versions`를 들어 올리고, `merge()`는 실행끼리
  지문이 갈리면 **비웁니다** — 그러면 게이트가 "기록 없음"으로 막습니다. 실행 도중에 본문을
  고쳤다면 세 실행의 평균이 무엇의 평균인지 말할 수 없습니다.
- `--write-baseline`은 실행끼리 지문이 다르면 **멈춥니다**(`judge_model`과 같은 모양). 다만
  보고서에 지문이 아예 없으면 기준선의 값을 **빈 값으로 덮지 않습니다** — `splits`·
  `related_slot`·`model_registry`가 조용히 사라진 세 번(ADR-034·ADR-032)과 같은 모양입니다.

### `git_sha`로는 대신할 수 없습니다

보고서는 이미 `git_sha`를 적습니다. 그것으로 충분하지 않은 이유가 둘입니다.

- 프롬프트를 **고치지 않은** 커밋에서도 점수는 흔들립니다. 그러면 `git_sha` 불일치가 매번
  올라오고, 매번 올라오는 규칙은 꺼집니다(ADR-004).
- 프롬프트를 **고친** 커밋에서도 다른 파일만 바뀌었을 수 있습니다. 그러면 놓칩니다.

**지문이 다르면 다른 프롬프트입니다.** 커밋이 아니라 본문에 걸어야 합니다.

### 분할에 매이지 않습니다

`judge_model`은 `metrics_split`이 맞을 때만 봅니다 — RAGAS 집계를 비교할 때만 뜻이 있기
때문입니다. 프롬프트는 다릅니다. 집계를 비교하지 않는 smoke 분할에서도 `stable_case` 규칙이
돌고, **그 규칙은 프롬프트가 바뀌면 뜻이 달라집니다.** 그래서 분할과 무관하게 봅니다.

### 기준선이 지문을 안 들고 있으면 아무것도 말하지 않습니다

규칙을 소급 적용하면 옛 기준선을 쓰는 모든 실행이 실패합니다. 반대로 **기준선은 들고 있는데
보고서가 비어 있으면 올립니다** — 지문이 없는 실행은 "같았다"가 아니라 "모른다"이고, 모르는
것을 통과시키면 규칙이 없는 것과 같습니다.

## 화면에도 올립니다

품질 게이트 탭이 규칙 일곱 개를 적고, 접은 칸에 **기준선의 지문과 지금 코드의 지문을 나란히**
보여 줍니다. 어긋나면 화면 맨 위에 경고가 뜹니다 — 그 상태에서 아래 숫자들은 **이 코드가 낸
점수가 아닙니다.**

테스트도 같은 것을 봅니다(`test_the_prompts_in_the_code_are_the_ones_the_baseline_was_measured_with`).
`prompts.py`를 고치면 CI의 평가 단계보다 **먼저** 알려 줍니다.

## 넘지 않은 선

**레지스트리를 런타임 경로에 넣지 않았습니다.** `pipeline/prompt_registry.py`가 MLflow에
버전을 올리지만, 앱이 질문마다 레지스트리를 조회하게 만들지 않습니다 — 그러면 배포 앱이
추적 서버에 매이고 그 서버가 죽을 때 챗봇이 죽습니다(ADR-016의 메모리 실측도 그 가정 위에
있습니다). 지문이 둘을 잇습니다. 게이트가 쓰는 값은 **저장소 파일에서 계산**되므로 CI에
토큰이 필요 없습니다.

**프롬프트가 바뀌었을 때 무엇이 맞는지는 코드가 모릅니다.** 규칙은 "달라졌다"만 말합니다.
고의로 고쳤다면 평가를 다시 돌리고 기준선을 다시 쓰는 것이 맞고, 그 판단은 사람이 합니다.

## 재현

```bash
uv run python -m pipeline.prompt_registry --manifest      # 지금 코드의 지문 (네트워크 없음)

```
