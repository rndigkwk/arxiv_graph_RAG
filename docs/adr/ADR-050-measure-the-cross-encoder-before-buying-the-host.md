
# ADR-050: 교차 인코더를 호스팅을 사기 전에 잰다 — 바를 먼저 적습니다

- **상태:** 채택 (측정 예정)
- **날짜:** 2026-10-20

## 맥락

[ADR-049](ADR-049-no-local-embedding-clears-the-bar.md)가 로컬 **양방향 인코더**를 닫았습니다 —
bge-base·bge-m3·Qwen3-0.6B 셋 다 `text-embedding-3-large`에 구간이 0을 제외하고 지고,
**크기가 아무것도 사지 않았습니다**(5.2배는 더 나쁘고, 5.5배는 1/5.5와 구별 안 됨).

그 뒤 "Cloud Run 4GB면 어떤 인코더가 되는가"라는 질문이 왔습니다. **4GB는 품질을 막고 있던
제약이 아니었습니다** — 기각한 셋이 전부 4GB 아래입니다(0.44 / 2.27 / 2.4GB). "4GB 이하
인코더"는 새 후보를 고르는 조건이 아니라 **방금 기각한 집합을 묘사하는 말**입니다.

## 결정 — 종류를 바꾸고, 호스팅보다 측정을 먼저 합니다

**교차 인코더(cross-encoder)를 잽니다.** bi-encoder는 두 논문을 따로 벡터로 만들어 코사인을
재고, 교차 인코더는 **둘을 함께 읽어** 점수를 냅니다. 간선이 없는 논문에서 코사인을 이길
**기전이 있는** 유일한 종류입니다. [ADR-031](ADR-031-the-model-that-wins-is-the-forecast.md)의
판별 기준으로 보면 이 자리가 유일하게 셋을 다 통과합니다.

| 기준 | 간선 0개 자리 |
|---|---|
| 라벨이 데이터 질의로 계산되지 않는가 | **통과** — 라벨이 미래입니다 |
| 양성이 충분한가 | **통과** — 1,112 시드 |
| 배포 제약에 맞는가 | **GPU/Cloud Run이 풀어 줍니다** |

**그런데 호스팅을 사서 알아보지 않습니다.** 측정이 배포를 요구하지 않습니다 — 점수를 밖에서
내고 판정은 저장소에서 합니다. ADR-039가 정한 순서("품질을 먼저 재고, 이기면 그때 배포 경로를
따진다")가 이미 두 번 값을 했습니다(ADR-046·ADR-049에서 배포 논의가 아예 필요 없었습니다).

**이기면** 그것이 Cloud Run 전환의 **세 번째 조건**이 됩니다(ROADMAP 8-5가 둘을 적어 뒀습니다).
**지면** 4GB 질문이 사라집니다.

## 넘어야 하는 바 — 재기 전에 적습니다

미래 라벨 과제의 **간선 0개 집단**(1,112 시드)에서 `vector` 변형(코사인)을 **구간이 0을
제외하도록** 이겨야 합니다.

| 지표 | 코사인의 현재 값 |
|---|---:|
| recall@5 | **0.1227** |
| hit@5 | **0.4739** |
| MRR | **0.3457** |

이 표를 ADR·노트북 양쪽에 **지금** 적어 둡니다. ADR-039에서 그렇게 해서 BGE-M3와 Qwen 결과를
보고 바를 움직일 수 없었고, 그 덕에 두 판정이 성립했습니다.

## 후보 집합을 밖에서 다시 만들지 않습니다

이 결정의 기술적 핵심입니다. 재정렬기는 **후보를 받아** 순서를 바꾸는 모델이므로, 후보가
다르면 비교가 성립하지 않습니다.

- 후보는 `벡터 상위 50 ∪ 보이는 공동인용`이고, 그 계산을
  [`pool_candidates`](../../evals/related_study.py) **한 곳**에 두었습니다. `graph-text-gbm`의
  `Reranker`와 내보내기가 같은 함수를 부릅니다 — 두 벌이 되면 "재정렬이 못 했다"와 "후보가
  달랐다"를 구별할 수 없습니다([ADR-029](ADR-029-ppr-beats-the-adapter-in-the-related-slot.md)).
- 들여올 때 **검증합니다.** 점수 파일에 이 하네스가 뽑지 않은 논문이 있으면 거부합니다 —
  다른 스냅샷이나 다른 `feature_cut`으로 내보낸 파일의 증거입니다.
- **텍스트도 굳혀 보냅니다.** 말뭉치의 문자열을 그대로 넘깁니다. 밖에서 다시 만들면 재는
  것이 모델이 아니라 **전처리 차이**입니다(ADR-039).
- **순위는 저장소가 매깁니다.** 밖에서는 점수만 냅니다 — 동점 처리까지 다른 변형과 같아야
  합니다.

## 쌍 길이를 1,024로 둡니다

임베딩 노트북은 512였습니다. 거기서는 입력이 논문 **하나**였고(제목+초록 토큰 중앙값 258,
512에서 초과 0.0%), 여기서는 입력이 **둘을 합친 것**입니다. 512로 자르면 앞의 시드가 먼저
채워서 **후보 쪽이 거의 다 잘립니다.** 자른 자리가 모델의 약점처럼 보이게 됩니다.

## 비용

쌍 68,182개(시드 1,377 × 후보 중앙값 49), 논문 24,360편, 전송 12MB. T4에서 한 시간 안쪽으로
봅니다 — **다만 어림입니다.** 2026-10-20에 Qwen 인코딩 시간을 어림했다가 2.2배 틀렸으므로,
노트북이 조각마다 실측 시간과 VRAM 피크를 찍습니다.

## 넘지 않은 선

**배포 지연을 아직 재지 않았습니다.** dograg가 같은 종류를 재고 기각했습니다 — 메모리
+600MB, **질문당 수십 초**, ONNX 4종 전부 쓸 수 없었습니다. 다만 그 숫자는 **질문당**이고
이 자리는 **후보 50편을 한 번** 재정렬합니다. 이기면 그때 "CPU에서 50쌍"을 재야 하고, 그것이
Cloud Run 판단의 입력입니다. 품질이 먼저입니다.

**학습하지 않습니다.** 사전학습 재정렬기를 그대로 씁니다. 미세조정은 이기는 것을 확인한
뒤에 물을 질문이고, 지금 물으면 두 변수를 함께 바꾸게 됩니다.
