# ADR-065: 화면이 논문마다 어떻게 찾았는지 말한다 — 후보를 지우지 않는다

- **상태:** 채택
- **날짜:** 2026-10-24

## 맥락

배포 앱에서 저자 질문("Yoshua Bengio가 쓴 논문이 있어?")을 하면 캡션이 이렇게 나왔습니다.

```
한국어→영어 번역: 선택됨 | 벡터 의미 검색: 선택 안 됨 | Text2Cypher: 선택됨 |
개인화 PageRank: 선택됨
```

그런데 그래프에는 **답변이 인용하지 않은 논문**이 함께 그려져 있었습니다. "벡터는 안 썼다"는
줄 아래에 벡터가 올린 논문이 있는 셈입니다.

세어 보니 **한 줄에 거짓이 둘, 표에 하나 더** 있었습니다.

| 화면이 적은 것 | 실제 | 어디 |
|---|---|---|
| `벡터 의미 검색: 선택 안 됨` | `rank_related_papers`가 빈자리를 **임베딩으로** 채웠습니다 | `app.py` 캡션이 `search_papers` 호출만 셌습니다 |
| `개인화 PageRank: 선택됨` | 주 경로는 **공동인용**입니다. PPR은 모자랄 때의 보조입니다 | 도구 이름을 보조 경로로 불렀습니다 |
| 표의 `PageRank` 열 | **세 단위가 섞입니다** — 공유 인용자 수(정수), PPR 점수(확률), 임베딩이 채운 논문은 `0.0` | `SCORE_COLUMN`이 한 이름으로 적었습니다 |

**필요한 값은 이미 있었습니다.** `rank_related_papers`가 논문마다 `ranked_by`를
`cocitation` / `pagerank` / `embedding` 중 하나로 붙입니다. 코드 주석도 그것을 가리킵니다 —
*"임베딩이 채운 논문은 둘 다 0이라 0.0이 됩니다 - `ranked_by`가 그것을 말합니다."*
**쓴 사람은 알고 있었고, 화면이 그 값을 읽지 않았습니다.**

이 프로젝트에서 반복되는 모양입니다([ADR-062](ADR-062-read-back-whether-langfuse-stored-it.md),
[ADR-064](ADR-064-the-pipeline-cannot-finish-without-leaving-the-pipeline.md)) — 진실을 말할
자료는 있고, 그것을 읽는 쪽이 없습니다.

## 결정

**표시가 `ranked_by`를 읽습니다. 후보는 테두리로 구분하고 지우지 않습니다.**

1. 캡션의 벡터 줄은 두 길을 **따로** 적습니다 — `search_papers` 호출과 관련 논문의 임베딩
   보충. 섞으면 어느 쪽인지 알 수 없고, 뒤쪽을 빼면 이번처럼 거짓이 됩니다.
2. 도구를 `관련 논문: 공동인용 N편 · 개인화 PageRank N편 · 임베딩 보충 N편`으로 적습니다.
   호출했지만 결과가 빈 경우는 **호출하지 않은 것과 구분**합니다.
3. 표에 `찾은 방법`과 `점수 단위` 열을 넣고, 점수 열 이름을 한 메커니즘에서 떼어냅니다.
4. 그래프는 근거로 인용한 논문을 실선, 공동인용·PPR 후보를 파선, 임베딩이 채운 후보를
   점선 테두리로 그리고, **범례를 캡션에 적습니다.**

캡션 조립을 `route_marks(response)` 순수 함수로 뺐습니다. 테스트가 화면을 거치지 않고 이
함수를 직접 봅니다 — 거짓말하던 줄을 테스트가 직접 읽게 하려고.

### 기각: "그래프 입력을 `evidence_ids`로 제한"

재검토 문서가 제안한 처방입니다. **택하지 않았습니다.**

그려지던 후보는 벡터 결과가 아니라 **공동인용으로 올라온 논문**이고, 공동인용은
[ADR-034](ADR-034-measure-every-eligible-seed.md)가 적격 시드 전부(3,740건)에서 recall@5
**0.8892 대 0.3957**로 개인화 PageRank의 2.2배라고 잰 결과입니다(쌍체 구간이 0을 제외합니다).
`evidence_ids`로 제한하면 **이 프로젝트가 재서 이긴 것을 화면에서 지웁니다.**

문제는 후보가 그려지는 것이 아니라 **어떻게 들어왔는지 말하지 않는 것**이었습니다. 관찰은
맞았고 진단이 틀렸습니다 — [11-43절](../../EXPERIMENTS.md)에서 18배를 잘못 잰 것과 같은
종류입니다. 재검토 문서가 괄호로 덧붙인 대안("또는 인용되지 않은 후보로 흐리게")이 맞는
쪽이었습니다.

## 같이 쟀습니다 — 답변 지연은 두 노드가 전부입니다

"35초 중 어디가 긴지"를 재려 했는데 **돈을 쓸 필요가 없었습니다.**
`agent_graph.summarize_trace`가 노드마다 초를 남기고, 기준선 보고서 90건이 그것을 담고
있습니다([`scripts/measure_answer_latency.py`](../../scripts/measure_answer_latency.py)).

| | p50 | p90 | 최대 |
|---|---:|---:|---:|
| routed 90건 | <!--n:reports/answer_latency.json#modes.routed.p50-->15.495<!--/n-->초 | <!--n:reports/answer_latency.json#modes.routed.p90-->21.29<!--/n-->초 | <!--n:reports/answer_latency.json#modes.routed.max-->42.51<!--/n-->초 |

**"약 35초"는 p50이 아니라 꼬리입니다.** 그리고 전체가 두 노드에 있습니다 —
`generate` <!--n:reports/answer_latency.json#modes.routed.nodes.0.share-->0.728<!--/n-->,
`check_conditions` <!--n:reports/answer_latency.json#modes.routed.nodes.1.share-->0.272<!--/n-->.
나머지 노드(`route`·`collect`·`check_format`·`accept`)는 전부 0.00초입니다.

**자기 검사가 기다림의 4분의 1입니다.** 조건 판정([ADR-020](ADR-020-judge-called-once.md))에
처음으로 값이 붙었습니다. 지금 끄지 않습니다 — 그 검사가 무엇을 잡는지는
[11-38절](../../EXPERIMENTS.md)이 고장 주입으로 쟀습니다.

**[ADR-024](ADR-024-route-by-question-type.md)의 가족별 p50은 저장소의 어느 파일로도
재현되지 않습니다.** routed(15.495)도 resolve(13.13)도 그 표(author 12.2 / citing 10.5 /
coauthor 17.5 / reference 13.9 / topcited 11.5)와 맞지 않습니다. 그 수는 덮여 쓰인 실행에서
나왔고 출처에 묶여 있지 않습니다. 그 ADR에 재현 불가로 적었습니다.

## 민감도

**바뀌는 조건.**

- `rank_related_papers`가 `ranked_by`에 새 값을 더하면 표찰과 테두리가 비어 보입니다.
  테스트가 네 값 전부에 표찰이 있는지 봅니다.
- 지연 분해는 **하네스 실행**입니다. 앱은 위에 Streamlit 렌더링, 한국어 번역 도구 호출,
  부분 그래프 조회, PageRank 패널을 더합니다. 그래서 이 수는 앱의 **하한**입니다.
- 두 노드 밖이 5%를 넘으면 모양이 바뀐 것이고, 스크립트가 그렇게 말합니다(`shape_held`).

**말하지 않는 것.**

- **`generate` 안쪽.** 번역·Text2Cypher·벡터·모델 턴의 몫을 가를 수 없습니다 — 도구 호출에
  소요 시간이 기록되지 않습니다(`tool_calls`에 `seconds`가 없습니다). 그 아래를 보려면 도구
  호출에 시간을 남기는 수정이 먼저이고, **이 ADR은 그것을 하지 않았습니다.**
- **답변이 더 정확해지는지.** 이 변경은 화면이 사실을 말하게 할 뿐이고 검색 결과를 바꾸지
  않습니다. 평가 수치는 그대로입니다.
- **후보를 보여 주는 것이 사용자에게 도움이 되는지.** 지우지 않기로 한 근거는 ADR-034의
  검색 품질이고, "화면에 띄웠을 때 사람이 더 잘 고르는가"는 재지 않았습니다.
- **세 칸 배치와 가족별 게이트 패널.** 같은 재검토 문서의 항목인데 이 ADR에 없습니다 —
  전자는 대화 기록을 어떻게 할지 정해야 하고, 후자는 가족별 수가 `cases: 6`뿐입니다.
