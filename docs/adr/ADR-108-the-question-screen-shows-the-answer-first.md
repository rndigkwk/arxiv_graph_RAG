# ADR-108: 질문 화면은 답을 먼저 보여 준다 — 한국어 질문은 답이 오자마자 번역한다

- **상태:** 채택
- **날짜:** 2026-11-06

## 맥락

2026-11-06 강사 피드백 중 하나는 "웹 화면이 사용자보다 개발자를 위한 화면"이라는 것이었습니다. 배포 화면을
점검하니 그 말이 맞았습니다("Yoshua Bengio가 쓴 논문이 있어?"로 확인).

- **답이 영어이고, 한국어는 버튼 뒤에 있었습니다.** 버튼은 근거 표 아래에 있었습니다. 질문 대부분이 한국어입니다.
- **같은 25편 표가 두 번 나왔습니다.** 한 번은 답 안의 마크다운 표, 한 번은 "근거로 쓴 논문" 표였습니다.
  페이지 높이는 4,155px였습니다.
- **개발자용 기록이 답과 같은 높이에 있었습니다.** 오른쪽 칸에 Cypher, 단계별 시간, 도구 순서가 있었습니다.
  머리줄에는 커밋 해시가 있었습니다.
- **조회가 `LIMIT 25`에서 끊겨도 아무 말이 없었습니다.** 25편이 전부인 것처럼 읽혔습니다.
- **입력칸 안내가 영어였고**, "예측 모델" 같은 내부 용어가 그대로 보였습니다.

시안을 먼저 만들어 지금 화면과 나란히 놓고 정했습니다
([질문 화면 시안](https://claude.ai/artifact/JxCekMYiN6hx2zRaigB9rg)).

## 결정

**순서를 질문 → 답 → 근거 논문 → 이어서 읽을 논문 → "어떻게 찾았나"(접힘)로 바꿉니다.**

- **한국어로 물으면 답이 오자마자 번역을 부릅니다.** 영어 답을 먼저 보여 주고, 번역이 오면 한국어로
  바꿔 끼웁니다. "한국어 / 원문 (English)" 단추로 오갑니다. 영어로 물으면 번역하지 않고
  "한국어로 보기" 버튼만 둡니다. 판정은 질문에 한글이 있는지입니다(`hasHangul`).
  8,000자(`MAX_TRANSLATE_CHARS`)를 넘는 답은 부르지 않습니다.
- **번역은 질문과 상한을 따로 셉니다.** `/api/translate`는 `API_TRANSLATE_*` 환경변수를 읽고, 기본값은
  질문과 같습니다(IP마다 분당 3·하루 30, 전체 하루 300). 같이 세면 한국어 질문 하나가 상한을 두 칸 써서,
  [ADR-081](ADR-081-fastapi-beside-streamlit-on-the-vm.md)의 질문 상한이 사실상 절반이 됩니다.
- **근거 표는 한 번만 보여 주고 카드로 바꿉니다.** 처음에는 5편만 보여 주고, 나머지는 "N편 모두 보기"로
  폅니다. 제목, 첫 저자, 분류는 답이 아니라 그래프에서 읽습니다(전과 같습니다).
- **조회가 `LIMIT`에서 끊기면 그렇다고 씁니다.** 돌아온 행이 Cypher의 `LIMIT`과 같으면 "그래프 조회가
  N편에서 멈췄습니다. 더 있을 수 있어요"라고 씁니다(`rowCap`).
- **개발자용 기록은 맨 아래 "어떻게 찾았나" 하나로 접습니다.** Cypher, 돌아온 행, 근거 대조, 단계별 시간,
  도구 순서, 벡터 검색 초록이 들어갑니다. 접힌 줄에 경로, 조회 수, 시간을 한 줄로 적습니다. 근거 그래프도
  "근거를 그래프로 보기"로 접습니다.
- **입력 전 경로 미리보기를 화면에서 뺐습니다.** 타자를 멈출 때마다 `/api/route`를 부르던 "→ 그래프 경로
  · 모델 없이, 0원" 줄입니다. 쓰는 경로는 "어떻게 찾았나"에 남깁니다. `/api/route`와 `routeLine`은 그대로
  둡니다.
- **배포 커밋은 머리줄에서 맨 아래 바닥줄로 내렸습니다.**
- **공통 토큰을 둡니다.** `globals.css`에 글자 크기(`--fs-*`: 28/22/17/16/15/13/12), 간격(`--space-*`:
  4~48), 모서리(`--radius-*`: 8/10/12), 누를 자리(`--tap`: 44px)를 넣었습니다. 본문은 14px에서 15px로
  올렸습니다. 논문·탐색 화면도 다음 작업에서 이 토큰으로 옮깁니다.

## 고르지 않은 것

- **지시문을 바꿔 처음부터 한국어로 답하게 하기.** 답은 영어가 설계입니다(`src/prompts.py`). 지시문을
  바꾸면 모든 턴이 느려질 수 있고, 판정이 보는 입력이 바뀌므로 유료 평가를 먼저 돌려야 합니다.
- **모든 질문을 번역하기.** 영어로 물은 사람은 영어 답을 원할 가능성이 높습니다. 그런 질문까지 번역하면
  비용만 듭니다.
- **번역을 질문 상한 안에 두기.** 비용은 묶이지만, 한국어 질문이 분당 1.5개, 하루 15개로 줄어듭니다.

## 민감도

- **한국어 답은 영어 답보다 늦게 뜹니다.** 11-06 VM 확인 때 번역이 1.97초였습니다
  ([ADR-105](ADR-105-recent-uses-the-period-the-question-names.md)). 그동안은 영어 원문과
  "한국어로 옮기는 중…"을 보여 줍니다. 답 지연 측정(`measure_vm_answer_latency.py`)은 `/api/ask`만 재므로
  이 2초는 들어가지 않습니다.
  **2026-11-07에 쟀습니다**(`--examples`, 화면의 한국어 예시 7문항, `reports/vm_answer_latency_examples.json`).
  번역은 p50 2.52초였고, 25행 표가 든 답은 7초까지 걸렸습니다. 한국어 답이 뜨기까지(받는 쪽 답 + 번역)
  p50 12.12초, p90 22.46초, 10초 안은 1/7입니다. 서버만 보면 p50 10.01초로, 영어 15문항(6.09초)보다 깁니다 -
  질문을 영어로 옮기는 노드가 p50 1.69초를 더합니다. 목표 10초는 영어 질문에서만 지킵니다.
- **번역 비용이 한국어 질문마다 듭니다.** 번역은 짧은 입력 한 번이라 질문보다 훨씬 쌉니다. 그래도 전체
  하루 상한(300)이 번역에도 따로 있어, 최악의 하루 비용은 질문 상한만 있을 때보다 커집니다.
- **`rowCap`은 마지막 `LIMIT`만 읽습니다.** 하위 질의의 `LIMIT`이나 `LIMIT $limit` 같은 매개변수는 못
  읽고, 그때는 안내를 띄우지 않습니다. 틀리면 말을 덜 하는 쪽입니다.
- **번역문은 판정을 거치지 않습니다.** 근거와 대조된 것은 영어 원문입니다. 화면이 그 말을 적고 원문
  단추를 둡니다.
