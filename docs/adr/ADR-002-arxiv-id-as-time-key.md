# ADR-002: 시간 기준은 `published`가 아니라 arXiv ID의 `YYMM`

- **상태:** 채택
- **날짜:** 2026-10-15

## 맥락

링크 예측과 임베딩 학습은 **시간으로 데이터를 나눠야** 합니다. 미래 정보가 학습에 섞이면
점수가 전부 무의미해집니다. 분할 키로 `published` 필드를 쓰려 했습니다.

## 결정

시간 키는 **arXiv 신식 ID의 `YYMM`** 입니다(`2601.00001` → 2026-01). `published`는 분할에
쓰지 않습니다.

## 근거

OAI-PMH로 수집한 분량의 **27%(1,748편)** 가 발행일 자리에 **수집 창 날짜**를 갖고 있었습니다.
그 값으로 나누면 2020년 논문이 2026년 10월에 발행된 것으로 분류됩니다.

arXiv ID의 `YYMM`은 **최초 제출 시점**이고 나중에 바뀌지 않습니다. 개정판이 올라와도 ID는
그대로입니다.

## 대가

구식 ID(`cs.LG/0601001` 형태)는 별도 정규식으로 처리해야 합니다. 월 단위까지만 알 수 있어
일 단위 분할은 불가능합니다 — 이 과제에서는 월이면 충분합니다.

## 민감도

**거의 흔들리지 않습니다.** ID 규칙은 arXiv가 정한 불변값입니다. 수집 경로를 OAI-PMH에서
다른 API로 바꿔도 결론이 유지됩니다.

## 재현

품질 게이트의 `month_key_coverage`(≥0.99)와 `citation_time_order`(≤0.02)가 이 가정을 매
스냅샷에서 검사합니다 — [`pipeline/quality.py`](../../pipeline/quality.py).
