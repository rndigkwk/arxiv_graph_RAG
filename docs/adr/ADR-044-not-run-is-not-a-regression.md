# ADR-044: 돌리지 못한 것은 회귀가 아니다 — 그러나 통과도 아니다

- **상태:** 채택
- **날짜:** 2026-10-19

## 맥락

2026-10-19에 PR #13에서 필수 검사 `evaluate`가 빨갛게 떴습니다. 로그를 열어 보니 품질과
무관했습니다.

```
Error code: 429 — 'code': 'project_spend_limit_exceeded'
'Your project has reached its configured enforced spend limit.'
```

평가의 **첫 임베딩 호출**에서 났고, 재시도 두 번도 같은 429를 받았습니다. 화면에 보이는 것은
**품질이 회귀했을 때와 똑같은 빨간 X** 하나였고, 어느 쪽인지 알려면 트레이스백 40줄을 읽어야
했습니다.

이 저장소는 이미 같은 구별을 두 번 했습니다.

| 구별 | 어디서 |
|---|---|
| 채점 함수가 죽은 것 ≠ 에이전트가 실패한 것 | `scoring_error` vs `answer_failure_rate` (ADR-017) |
| 프롬프트가 달라진 것 ≠ 점수가 내려간 것 | `prompt_version` ([ADR-041](ADR-041-the-gate-reads-the-prompt.md)) |
| **평가를 돌리지 못한 것 ≠ 품질이 내려간 것** | 이 결정 |

## RAGAS 쪽은 더 나빴습니다

`ragas_study.score_one`은 지표마다 예외를 잡아 `None`을 적고 계속 갑니다 — 한 지표의 실패가
나머지를 막지 않게 하려는 올바른 설계입니다. 그런데 **예산이 바닥나면 네 지표가 전부 None이
되고**, 게이트는 그 보고서를 이렇게 읽습니다.

```
[floor] ragas_faithfulness이 이번 결과에 없습니다
```

`floor` 위반, 즉 **품질 하한을 못 넘었다**로 보고됩니다. 돌리지 못한 것이 품질 실패로 바뀌어
적히는 것이고, 기준선과 대조한 숫자가 하나도 없는데 하한 위반이 올라옵니다.

## 결정

[`evals/budget.py`](../../evals/budget.py)가 예산 소진을 판별하고, 두 하네스가 그것만
가로챕니다.

| | 전 | 후 |
|---|---|---|
| `evals.run` | 트레이스백, 보고서 없음 | 표식 + `::error::` + 종료 코드 **78** |
| `evals.ragas_study` | 네 지표 None → `floor` 위반 | 즉시 올리고 같은 표식 |
| CI 요약 | "앞 단계의 로그를 보세요" | **"평가를 돌리지 못했습니다 — 품질 회귀가 아닙니다"** |

### 통과로 바꾸지 않습니다

이것이 이 결정의 경계입니다. **돌리지 못한 검사는 통과가 아닙니다.** `evaluate`는 여전히
실패하고 머지는 여전히 막힙니다. `continue-on-error`도 넣지 않았고, 테스트가 그것이 들어오지
않았는지 봅니다.

바뀌는 것은 하나입니다 — **왜 실패했는지가 로그 깊은 곳이 아니라 요약 첫 줄에** 적힙니다.
ADR-004가 "터지는 게이트는 꺼진다"고 적었는데, 그 반대쪽 함정도 같습니다. **이유를 말하지
않는 게이트는 무시됩니다.**

### 일시적 429와 구별합니다

같은 HTTP 상태 코드가 두 가지를 뜻합니다.

| 코드 | 뜻 | 맞는 대응 |
|---|---|---|
| `rate_limit_exceeded` | 분당 요청 한도 | **재시도** — `neo4j_graphrag`·`tenacity`가 이미 합니다 |
| `insufficient_quota` 계열 | 예산 소진 | **멈추기** — 기다려도 풀리지 않습니다 |

예산 소진만 가로챕니다. 일시적 한도를 함께 잡으면 **재시도가 맞는 대응인데 멈춰** 버립니다.

### 문자열로 판별합니다

타입으로 잡지 않은 이유는 실제 예외가 두 겹 싸여 오기 때문입니다.

```
tenacity.RetryError
  └ neo4j_graphrag.exceptions.EmbeddingsGenerationError
      └ openai.RateLimitError   ← 코드가 여기 있습니다
```

감싸는 쪽을 전부 알아야 타입으로 잡을 수 있고, 라이브러리가 바뀌면 조용히 놓칩니다. 그래서
예외 사슬(`__cause__`/`__context__`)과 `code`·`body` 필드, `tenacity`의 실패한 Future까지
훑어 공급자 코드 문자열을 찾습니다. 문구가 아니라 **코드**를 봅니다.

## 어디까지 돌았는지 적습니다

표식에 `cases_done`을 넣습니다. **0건과 12건은 다시 돌릴 때 할 일이 다릅니다** — 전자는 한
건도 못 돌린 것이고, 후자는 도중에 떨어져 부분 결과가 보고서에 남아 있습니다.

## 곁에서 한 작은 정리

`evals.run`의 사례 루프가 세 갈래(`compare`·`retrieval`·`agent`)를 품고 있어서 **루프를 감쌀
수 없었습니다.** `one_case()`로 떼어 냈습니다 — 루프가 한 줄이어야 그 한 줄을 감쌀 수 있습니다.
행동은 바뀌지 않습니다.

## 넘지 않은 선

**남은 예산을 미리 보지 않습니다.** OpenAI에 "얼마 남았나"를 묻는 호출을 평가 앞에 두면 그
호출 자체가 실패 지점이 되고, 통과했다고 해서 평가 중에 안 떨어진다는 보장도 없습니다. 떨어진
뒤에 **정확히 말하는** 쪽을 골랐습니다.

**자동으로 다시 돌리지 않습니다.** 예산은 사람이 올려야 풀립니다. 재시도를 걸면 한도에 닿은
채로 워크플로가 반복되고, Actions 분만 씁니다.
