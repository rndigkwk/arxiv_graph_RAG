# ADR-115: 끊긴 답과 모델 장애를 화면이 알린다 — 끝 이벤트 없는 스트림은 오류, 장애는 할 일로

- **상태:** 채택
- **날짜:** 2026-11-09

## 맥락

[교안 Day 77](../lecture-review.md#fastapi-모델-서빙-api-day-77)은 서빙 API의 스트림을 두 가지로 다룹니다.

- 첫 조각 뒤에는 상태 코드를 바꿀 수 없으므로, 클라이언트는 끝 줄(`[DONE]`)을 받았는지로 완료를 판단합니다.
- 백엔드 실패는 종류별로 알립니다(시간 초과 504, 연결 실패 502).

이 프로젝트와 맞춰 보니 두 군데가 비어 있었습니다.

1. **질문 스트림이 끝 이벤트 없이 닫히면 웹이 아무것도 하지 않았습니다.** `web/lib/api.ts`의 `ask()`는 `final`·`abstain`·`error`가
   오지 않아도 조용히 끝났습니다. 그 턴은 `streaming`에 남고, `busy` 때문에 입력창과 "새 질문"이 새로고침할 때까지 막혔습니다.
   API 재시작이 진행 중인 답을 끊는다는 것은 [ADR-107](ADR-107-restart-the-api-only-when-it-reads-the-change.md)에 적혀 있습니다.
   번역 스트림은 이미 이 경우를 오류로 처리했습니다([ADR-114](ADR-114-the-translation-streams.md)).
2. **웹 API의 오류 문장이 늘 "다시 시도해 주세요"였습니다.** `src/model_outage.py`는 예외를 "사용 한도 소진"과 "제공자 무응답"으로 나누고,
   Streamlit은 그 문장을 보여 줍니다. 한도가 다 된 날에는 다시 물어도 같은 실패가 납니다.

## 결정

- **`ask()`는 끝 이벤트 없이 닫힌 스트림을 `error`로 끝냅니다.** 문장은 "답이 중간에 끊겼습니다. 다시 물어 주세요."입니다.
  끝 이벤트를 받으면 바로 돌아갑니다.
- **`/api/ask`의 `error` 이벤트는 모델 장애이면 `model_outage.web_message`를 씁니다.** 이유 문장은 Streamlit과 같습니다.
  뒤에 붙는 "모델 없이 되는 곳"만 웹 화면 이름으로 바꿉니다(논문·탐색·품질·그래프). 모델 문제가 아니면 지금 문장 그대로입니다.
  예외 이름(`type`)은 지금처럼 함께 보냅니다.
- **번역 실패는 바꾸지 않습니다.** 화면이 번역 실패에 "번역하지 못했습니다 · 다시 시도" 버튼만 보여 주고 서버 문장을 쓰지 않습니다.
- **HTTP 상태 코드(502·504)로 나누지 않습니다.** 질문은 SSE라 첫 바이트에 이미 200이 나갑니다. 화면이 읽는 것은 문장입니다.

## 고르지 않은 것

- **재시작할 때 진행 중인 답을 기다리기**(uvicorn의 종료 대기를 늘리기). 답이 6~20초라 배포마다 그만큼 늦어집니다. 그래도
  연결이 끊기는 다른 경우(VM, Caddy, 네트워크)는 남습니다. 화면이 끊김을 알아보는 쪽이 모든 경우를 덮습니다.
- **끊긴 답을 자동으로 다시 묻기.** 질문은 IP당 분당 3번으로 막혀 있고, 다시 묻기는 비용이 듭니다. 사람이 고르게 둡니다.

## 민감도

- **실제로 멈춘 화면을 본 적은 없습니다.** 코드를 읽고 찾은 경우입니다. 연결이 리셋되면 `fetch` 읽기가 예외를 내고, 기존 `catch`가 이미
  오류로 바꿨습니다. 이번 변경은 연결이 깔끔하게 닫히는 경우를 덮습니다.
- **`src/`가 바뀌어 머지하면 VM API가 다시 뜹니다**([ADR-107](ADR-107-restart-the-api-only-when-it-reads-the-change.md)).
