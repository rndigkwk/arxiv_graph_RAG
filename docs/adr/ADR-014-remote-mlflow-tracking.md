# ADR-014: 학습 추적은 실행 VM이 아니라 원격 MLflow 서버에 남긴다

- **상태:** 채택
- **날짜:** 2026-10-16

## 맥락

Colab 파인튜닝을 `report_to=[]`로 돌려서 스텝별 손실이 **어디에도 남지 않았습니다.** 급히
`TrainerCallback`으로 CSV를 쓰게 고쳤지만, 그것은 실행 중인 VM 안에 쓰는 방식입니다. 실제로
커널이 죽어 1,100스텝에서 끊긴 CSV만 남고 학습이 끝났는지조차 알 수 없었습니다.

## 결정

학습 추적은 **원격 MLflow 서버**(DagsHub, `https://dagshub.com/rndigkwk/arxiv_graph_RAG.mlflow`)로
보냅니다. `mlruns/`를 실행 VM에 쓰는 구성은 쓰지 않습니다.

## 근거

**실행 환경과 기록 위치가 같은 기계에 있으면 기록이 아니라 착각입니다.** 런타임이 끊기면
업로드 전까지 아무것도 보장되지 않습니다.

무료 선택지를 비교했고 DagsHub를 골랐습니다 — 호스팅 MLflow가 무료 등급에 포함되고, 추적
URI가 **저장소별**이라 프로젝트가 섞이지 않습니다. 자체 호스팅은 서버를 먼저 띄워야 하므로
"학습을 지금 돌려야 한다"는 상황과 맞지 않았습니다.

## 함께 넣은 장치

| 장치 | 이유 |
|---|---|
| 스텝 체크포인트(`SAVE_STEPS`) | 커널이 죽어 3시간을 두 번 잃었습니다 |
| `RESUME_FROM_SAVED` | 학습과 채점이 한 함수에 묶여 있어 재시작이 전부 재학습이었습니다 |
| `RUN_SUFFIX` / `run_path()` | SMOKE와 본 실행이 산출물 경로를 공유해, 400쌍 모델이 본 결과로 채점될 수 있었습니다 |
| `pipeline/tracking.py`의 `.env` 로딩 | 설정한 URI를 읽지 못해 런이 조용히 로컬 `mlruns/`로 가고 있었습니다 |

## 대가

토큰이 필요합니다. 토큰은 **로컬 `.env`에만** 두고 GitHub Secrets에는 넣지 않습니다. Colab에서는
`getpass`로 받으며 노트북에 기록되지 않습니다.

## 민감도

DagsHub 무료 등급의 조건이 바뀌면 재검토합니다. **TensorBoard가 대안**입니다 — 서버가 필요
없고 Colab에서 `%tensorboard`로 바로 보며, 이벤트 파일을 보고서와 함께 올리면 영속됩니다.
중앙 집계가 필요 없다면 그쪽이 더 쌉니다.
