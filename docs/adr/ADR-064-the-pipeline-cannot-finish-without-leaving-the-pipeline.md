# ADR-064: 파이프라인이 파이프라인 밖으로 나가야 끝난다 — 임베딩 단계를 안으로 가져온다

- **상태:** 채택 — 적재 완료. **가드가 통과하면서 손상이 일어났고, 되읽기를 추가했습니다**
- **날짜:** 2026-10-24

## 맥락

증분 수집 파이프라인에 **수동 단계**가 하나 끼어 있습니다. 가드의 오류 메시지가 그것을 직접
말합니다([`pipeline/ingest.py`](../../pipeline/ingest.py)).

> 임베딩을 먼저 만드세요(**notebooks/arxiv_ai_kg_to_aura.ipynb**). 적재한 뒤 바로 임베딩을
> 채울 계획이라면 `--allow-missing-embeddings` 로 넘기세요.

[ADR-047](ADR-047-the-loader-refuses-papers-the-vector-index-cannot-see.md)이 임베딩 없는 논문의
적재를 막는 것은 맞습니다 — 그 논문은 그래프 질의에는 나오지만 **벡터 검색에 영원히 안
나옵니다.** 문제는 그 가드를 통과할 방법이 **저장소 안에 없다는 것**입니다.

| | |
|---|---|
| `plan_embeddings` | 수집한 레코드가 `embedding` 필드를 갖고 있는지 **셉니다** |
| 그것을 **채우는 코드** | **없습니다**(임베딩 클라이언트는 `chatbot.py`에만 있습니다) |

그래서 [11-42절](../../EXPERIMENTS.md)의 967편이 `coverage 0.0`이고, 주간 크론은 **적재를
끝까지 할 수 없습니다.** 남은 길은 `--allow-missing-embeddings`로 밀어붙이는 것뿐이고 그것은
조용한 손상입니다.

### 그리고 기한이 있습니다

11-42절이 관계 여유를 이 배치 크기로 **4.2회**로 셌습니다. 11-43절이 가장 큰 삭제 후보
(AUTHORED 접기)의 지연을 통과시켰지만 **접기 결정은 아직 아닙니다.** 즉 지금 쓸 수 있는
여유는 그 4.2회뿐이고, 약 1.1개월입니다.

## 결정

**노트북의 임베딩 단계를 `pipeline/embed.py`로 옮기고 `--embed`로 켭니다.**

### 입력 문자열을 **바이트 단위로** 그대로 씁니다

노트북이 이 형식을 바꾸면 안 된다고 적어 뒀습니다.

> 입력 문자열은 `"{title}\n\n{abstract}"`이며, 이 형식을 바꾸면 기존 벡터와 어긋나 전부 다시
> 만들어야 합니다.

| | 값 | 출처 |
|---|---|---|
| 입력 | `f"{title}\n\n{abstract}"[:20000]` | 노트북 20번 칸 |
| 모델 | `text-embedding-3-large` | 기존 37,854편 전부 |
| 차원 | 768 | 기존 37,854편 전부 |
| 배치 | 128 | 노트북 |

**그래프에는 쓰지 않습니다.** 임베딩을 수집 레코드에 붙이기만 하고, 쓰는 일은 이미 가드가
걸린 `--load`가 합니다. 단계를 섞지 않습니다.

### 그래서 `--embed`는 `--load` 없이 쓸 수 없습니다

이 ADR의 첫 판은 재현 절차에 `--embed`만 적었습니다. **그러면 돈을 쓰고 버립니다** — 벡터는
메모리 레코드에 붙고 이 모듈은 그래프에 따로 쓰지 않으므로, 적재하지 않으면 그대로 사라집니다.
`--embed`를 혼자 주면 거부합니다.

그리고 임베딩은 **용량 검사 뒤에** 돕니다. 들어갈 자리가 없는 배치에 비용을 쓰지 않습니다.

### 돈을 쓰는 단계이므로 기본값이 아닙니다

`--embed` 없이는 지금과 똑같이 동작합니다. 유료 호출을 하는 단계가 기본으로 켜지면 시험
실행이 시험 실행이 아닙니다.

## 바 — 돈을 쓰기 전에 적습니다

### 1. 같은 벡터 공간인지 — **먼저 20편으로 확인합니다**

967편에 돈을 쓰기 전에, **이미 벡터를 가진 논문 20편**을 같은 코드로 다시 임베딩해 저장된
벡터와 코사인을 잽니다.

| | 조건 |
|---|---|
| **통과** | 20편 **전부** 코사인 ≥ **0.9999** |
| 하나라도 미달 | **967편을 임베딩하지 않습니다.** 입력 형식이나 모델 판이 어긋난 것입니다 |

### 2. 음성 대조군을 함께 돌립니다

**이것이 없으면 검사가 맞는지 알 수 없습니다.** 틀린 형식도 0.9999를 넘는다면 이 검사는
아무것도 가려내지 못합니다. 그래서 일부러 틀린 입력(`f"{title} {abstract}"` — 줄바꿈 둘을
공백 하나로)도 같이 재고 **그 차이를 적습니다.**

| | 조건 |
|---|---|
| **검사가 쓸모 있음** | 올바른 형식의 최소 코사인이 틀린 형식의 최대 코사인보다 **높음** |
| 둘이 겹침 | 검사가 형식을 가려내지 못합니다. **그 사실을 적고 967편을 멈춥니다** |

2026-10-23에 Langfuse 되읽기에서 **고장 난 검출기가 "저장 안 됨"이라는 그럴듯한 답을
내놨고**, 음성 대조군이 있어서 잡혔습니다. 같은 이유로 여기에도 둡니다.

### 3. 비용 천장

호출 전에 `tiktoken`으로 토큰을 세고 비용을 찍습니다. **추정 비용이 $1.00을 넘으면 거부**
하고 `--max-cost`로 올려야 돕니다. 실제 토큰 수와 비용을 보고서에 적습니다.

### 예측을 적습니다

`\n\n` 형식이 0.9999를 넘고, 공백 형식은 눈에 보이게 낮을 것으로 봅니다(0.97~0.995 정도).
967편 비용은 **약 $0.04**로 봅니다(편당 약 325토큰 × $0.13/1M).

**틀릴 수 있는 쪽.** 말뭉치를 임베딩한 때와 지금 사이에 모델 판이 바뀌었다면 **올바른 입력도
0.9999를 못 넘깁니다.** 그러면 967편을 기존 37,854편과 같은 공간에 넣을 방법이 없다는
뜻이고, 그것은 이 측정이 잡아야 하는 가장 중요한 결과입니다 — 밀어붙이면 벡터 검색이
말없이 두 공간으로 쪼개집니다.

## 결과 1 (2026-10-24) — 같은 공간입니다

20편을 다시 임베딩해 저장된 벡터와 비교했습니다.

| | 값 | 바 |
|---|---:|---|
| 최소 코사인 (올바른 형식) | **0.999986** | ≥ 0.9999 **통과** |
| 최대 코사인 (음성 대조군) | 0.989453 | 더 낮아야 함 **통과** |
| 차이 | 0.010533 | |

**음성 대조군이 0.0105 낮습니다.** 그래서 이 검사가 형식을 실제로 가려낸다고 말할 수
있습니다 — 공백 하나로 바꾼 입력은 0.9895에 머물고 바를 못 넘습니다. 대조군이 없었다면
0.999986만 보고 "맞다"고 했을 것이고, 그 수가 형식 때문인지 모델이 원래 비슷한 벡터를 주기
때문인지 구별할 수 없었습니다.

모델 판도 그대로입니다. 말뭉치를 만든 때와 지금 사이에 `text-embedding-3-large`가 바뀌었다면
올바른 입력도 0.9999를 못 넘겼을 것이고, 그러면 967편을 같은 공간에 넣을 방법이 없었습니다.

## 결과 2 (2026-10-24) — **가드가 통과하면서 손상이 일어났습니다**

934편을 임베딩하고($0.0351) 적재했습니다. 보고서가 이렇게 말했습니다.

```
embeddings: {new_papers: 811, with_embedding: 811, coverage: 1.0, ready: true}
idempotent: true
```

**그런데 그래프에는 811편이 임베딩 없이 들어갔습니다.**

```
임베딩 없는 논문: 811
이번 배치 934편 중 임베딩 있는 논문: 123   (= 전부터 그래프에 있던 것)
```

### 옳은 결정 둘이 곱해졌습니다

| | 그 자체로는 옳습니다 |
|---|---|
| `plan_embeddings`는 **수집 레코드**를 봅니다 | 적재 전에 막아야 하므로 상류에서 볼 수 있는 것을 봅니다 |
| `MERGE_PAPER`는 `embedding`을 **쓰지 않았습니다** | 같은 논문을 다시 적재할 때 갖고 있던 벡터를 지우지 않으려고 |

`--embed`가 레코드를 채우자 첫 번째가 `ready: true`라고 말했고, 두 번째가 그 값을 **버렸습니다.**
**가드는 의도를 재고 있었고 결과를 재지 않았습니다.** 그래서
[ADR-047](ADR-047-the-loader-refuses-papers-the-vector-index-cannot-see.md)이 막으려고 만든
바로 그 상태 — 그래프 질의에는 나오지만 벡터 검색에 안 나오는 논문 — 가 **그 가드가 초록불을
켠 채로** 만들어졌습니다.

[ADR-060](ADR-060-what-the-gate-catches-when-the-judge-collapses.md)의 게이트 구멍과 같은 모양입니다: 각각 타당한 두 결정의
**곱**이 구멍입니다.

### 고친 것

1. **`MERGE_PAPER`가 `coalesce`로 씁니다.** `coalesce(row.embedding, p.embedding)` — 레코드가
   가져왔을 때만 쓰고, 없으면 노드가 갖고 있던 것을 남깁니다. 두 요구를 동시에 만족합니다.
2. **적재 뒤 되읽습니다.** `verify_loaded_embeddings`가 적재한 `arxiv_id`로 **그래프에**
   물어보고, 100%가 아니면 `stopped_at: "loaded_without_embeddings"`로 적고 실패로 끝냅니다.
   상류 가드가 이것을 대신할 수 없습니다 — 그것은 레코드를 보고, 이것은 결과를 봅니다.
3. **중복 지출도 막았습니다.** 첫 실행은 수집한 934편 중 **이미 그래프에 벡터가 있던
   123편(13%)** 까지 임베딩했습니다. `already_embedded`를 넘겨 건너뜁니다.

### 복구

제목과 초록이 이미 노드에 있으므로 다시 수집하지 않았습니다 — `--backfill`이 벡터 없는 논문을
찾아 채우고 **되읽습니다.**

| | 값 |
|---|---:|
| 벡터가 없던 논문 | 811편 |
| 채운 논문 | **811편** ($0.0305) |
| 되읽은 뒤 남은 수 | **0** |

그리고 끝까지 확인했습니다 — 새 논문의 벡터로 인덱스를 조회하면 **자기 자신이 점수 1.0으로
1위**로 돌아옵니다. 인덱스 세 개 전부 `ONLINE` 100%입니다.

### 값으로 치른 대가

| | |
|---|---:|
| 벡터 공간 확인 | 약 $0.001 |
| 첫 임베딩 (버려짐) | $0.0351 |
| 복구 임베딩 | $0.0305 |
| **합계** | **약 $0.066** (제대로 했다면 $0.0305) |

**버린 $0.0351이 이 결함의 값입니다.** 그보다 큰 것은 되읽기가 없었다면 811편이 조용히 안
보이는 상태로 남았을 것이라는 점입니다 — 앱은 돌고 질문 일부만 답을 못 찾습니다.

## 민감도

**바뀌는 조건.**

- OpenAI가 `text-embedding-3-large`의 판을 바꾸면 코사인 검사가 떨어집니다. 그때는 재임베딩
  범위를 따로 판단해야 합니다(37,854편 전부 = 약 $1.6).
- `dimensions=768`은 3,072차원을 잘라 정규화한 것입니다. 이 인자를 빼면 다른 벡터가 됩니다.
- 초록이 20,000자를 넘으면 잘립니다. 기존 말뭉치도 같은 규칙으로 잘렸습니다.

**말하지 않는 것.**

- **검색 품질이 좋아지는지.** 이 단계는 새 논문을 **보이게** 만들 뿐이고, 얼마나 잘 찾는지는
  적재 뒤 평가가 말합니다.
- 적재 자체의 안전성. `--load`는 이미 ADR-047의 가드와 용량 검사가 지키고 있습니다.
- `evals/index_cost.py`의 토큰 추정은 `\n` 하나를 쓰므로 편당 1토큰쯤 다릅니다. **비용
  추정에는 무해**하고, 이미 기록된 보고서를 고치지 않기 위해 그대로 둡니다.

## 재현

```bash
# 벡터가 없는 논문을 채웁니다(유료, 그래프에 씁니다). 채운 뒤 되읽습니다
uv run python -m pipeline.embed --backfill --output reports/embedding_backfill.json
```

```bash
# 1단계: 돈을 쓰기 전에 벡터 공간이 같은지 20편으로 확인합니다(약 $0.001)
uv run python -m pipeline.embed --verify --output reports/embedding_space.json

# 2단계: 통과하면 수집 → 임베딩 → 적재를 한 번에 합니다
uv run python -m pipeline.ingest --days 7 --embed --load --output reports/ingest_embedded.json
```
