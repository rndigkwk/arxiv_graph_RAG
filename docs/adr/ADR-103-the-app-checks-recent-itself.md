# ADR-103: "최근" 조건은 앱이 발표일로 직접 확인한다 — 판정이 날짜 낱말만 적었을 때만

- **상태:** 채택
- **날짜:** 2026-11-05

## 맥락

"최근" 질문 6개를 VM에서 다시 쟀습니다(EXPERIMENTS 11-60, PR #114). 중앙값이 19.33초로, 10-28의 11.58초보다
느렸습니다. 답을 다시 쓴 문항은 2/6에서 4/6으로 늘었고, 다시 쓴 이유는 대부분 `graph_conditions_not_covered`였습니다.

모델은 힌트대로 `p.published >= datetime() - duration("P12M")`을 건 조회를 했습니다. 그런데 판정만 따로 불러 보니,
같은 입력에도 판정이 "최근"을 조건으로 적을지, 12개월 조회가 그것을 지키는지를 실행마다 다르게 봤습니다.
`diffusion-en`에서는 3번 중 2번 미충족이었습니다.

"최근 = 12개월"은 앱이 정한 뜻입니다([ADR-090](ADR-090-recent-is-a-date-filtered-search.md)). 판정은 그 뜻을 모릅니다.
앱이 정한 기준이므로, 지켰는지도 앱이 확인할 수 있습니다.

## 결정

판정이 "그래프 조건을 못 지켰다"고 봤어도, 다음 셋이 모두 맞으면 앱이 충족으로 바꿉니다(`candidate_validation.app_checks_recency`).

1. 질문이 "최근"을 묻습니다(`pre_recent.asks_recent`, ADR-090과 같은 낱말).
2. 판정이 적은 그래프 조건이 **모두 날짜 낱말뿐**입니다(`recent`, `"latest"`, `최근 논문` …). 저자·인용·분류·특정 연도가
   하나라도 있으면 판정의 결론을 그대로 둡니다.
3. 인용한 논문이 **모두** 최근 12개월 안에 발표됐습니다. 발표일을 읽지 못한 논문이 하나라도 있으면 바꾸지 않습니다.

바꾼 판정에는 `graph_checked_by_app: true`를 남깁니다. 날짜는 앱이 봤으므로, 인용한 논문이 그래프 조회 행에 없어도
막지 않습니다. 내용 일치(`content_matches`)는 그대로 봅니다.

**판정의 지시문과 입력은 바꾸지 않습니다.** 논문 조회에 발표일을 더했지만, 판정에는 지금처럼 ID·제목·초록만 보냅니다
(`judge_view`). 조건 판정 자체는 그대로 남습니다([ADR-069](ADR-069-the-condition-check-keeps-its-quarter.md)). 바뀌는 것은
앱이 정의한 조건 하나의 확인 주체뿐입니다.

## 근거 — main과 동시에 돌린 짝

로컬 앱(Aura)에서 main(`ae578c4`)과 이 브랜치를 **동시에** 돌렸습니다. "최근" 6문항을 3번씩, 18쌍입니다.
보고서는 [`reports/recent_covered_by_app_pairs.json`](../../reports/recent_covered_by_app_pairs.json)입니다.

| | main | 이 결정 |
|---|---:|---:|
| 답하지 못함(두 번 다 거절) | **2** | 0 |
| 답을 다시 씀 | 6 | 2 |
| 앱이 날짜를 확인함 | — | 11 |
| 중앙값(실패 포함) | 12.65초 | 10.41초 |
| p90 | 20.72초 | 15.76초 |
| 평균 모델 턴 | 3.06 | 2.33 |

짝 차이의 평균은 −2.50초 [−4.89, −0.19]입니다(부트스트랩 95%). 18쌍 중 10쌍이 빨랐습니다.

가장 큰 차이는 시간이 아니라 **답하지 못한 2번**입니다. main에서는 두 시도가 모두 거절당해 사용자가 오류를 받았습니다
(rlhf-ko 1회차, gnn-en 2회차). 이 결정에서는 0번이었습니다.

남은 재시도 2번은 둘 다 rlhf-ko입니다. 로컬 실행은 첫 시도의 거절 이유를 남기지 않아, 무엇 때문에 다시 썼는지는
가르지 못했습니다. rlhf-ko는 main에서도 세 번 모두 문제였습니다(실패 1, 재시도 2).

## 고르지 않은 것

- **판정 지시문에 "최근은 12개월" 한 줄 넣기.** 판정 입력을 바꾸면 판정 연구 61문항과 보류 질문을 다시 재야 합니다
  ([ADR-059](ADR-059-the-judge-prompt-is-measured-on-held-out-questions.md)). 게다가 날짜 비교는 모델보다 코드가 정확합니다.
- **판정에 발표일을 보내기.** 위와 같은 이유로, 판정 입력이 바뀝니다.

## 민감도

- 18쌍은 로컬(Aura)입니다. VM 효과는 머지 뒤 `measure_vm_answer_latency.py --recent`로 다시 잽니다.
- 날짜 낱말 목록(`pre_recent.CUES`)과 같이 지워도 되는 말(`FILLER`)은 영어·한국어 몇 개입니다. 목록에 없는 표현이면
  지금처럼 판정을 따르므로, 틀리는 방향은 "느림"이지 "잘못 통과"가 아닙니다.
- 회귀 평가 90문항에는 "최근" 질문이 없어서, 이 결정으로 결과가 바뀌지 않습니다.
