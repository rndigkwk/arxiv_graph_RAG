# ADR-116: 문항당 출력이 길면 회귀 평가가 경고한다 — 판정은 바꾸지 않는다

- **상태:** 채택
- **날짜:** 2026-11-09

## 맥락

2026-11-02 정기 평가에서 `citing-06-p1`의 판정 한 번이 출력 128,424토큰과 1,442초를 썼습니다([ADR-101](ADR-101-retry-a-broken-condition-verdict.md)).
평가는 그것을 근거 재현율이 떨어진 뒤에야 알렸습니다. 토큰 수는 보고서의 각 사례(`chat_output_tokens`)에 있었지만,
게이트는 토큰을 품질 지표가 아니라고 보고 읽지 않았습니다(`NOT_A_QUALITY_METRIC`).

ADR-101 뒤로 판정 한 번은 4,000토큰에서 잘리고, 잘리면 한 번 더 부릅니다. 같은 일이 다시 나도 재현율은 떨어지지 않을 수
있습니다. 그래서 길어진 것 자체를 따로 봐야 합니다. 상한이 없는 답 쓰는 에이전트가 길어지는 경우도 같습니다.
[교안 정리](../lecture-review.md)의 🟢 6번입니다(Day 73·75).

## 결정

- **게이트가 사례마다 출력 토큰을 들고 옵니다**(`normalize`의 `output_tokens`). 여러 실행을 합칠 때는 가장 긴 값을 남깁니다.
  한 번이라도 길어진 것을 봐야 하기 때문입니다. 품질 지표에는 넣지 않아 기준선과 비교하지 않습니다.
- **요약(`reports/summary.md`, CI 단계 요약)에 문항당 출력 최대와 그 사례를 늘 적습니다.**
- **5,000토큰(`OUTPUT_TOKEN_ALARM`)을 넘은 사례는 "출력이 긴 사례 (위반 아님)"에 적고 GitHub 경고(`::warning`)로 띄웁니다.**
  - 정상 실행의 최대는 1,085토큰이었습니다(ADR-101).
  - 판정이 상한 4,000에 닿아 다시 불리면 그 문항은 5,000을 넘습니다.
  - 지금 남아 있는 보고서(`baseline_resolve_run3_setmetrics.json`)의 최대는 1,151토큰이라 경고가 뜨지 않습니다.
- **판정(통과·실패)은 바꾸지 않습니다.** 실패로 막을지는 몇 주 값을 본 뒤에 정합니다.

## 고르지 않은 것

- **바로 위반으로 막기.** 기준이 될 분포가 실행 몇 번뿐입니다. 정상 실행이 우연히 길어져 PR이 막히면 경고를 끄게 됩니다.
- **평균 출력 토큰을 집계 지표로 비교하기.** 128,424토큰 하나가 평균을 움직이는 것은 맞지만, 90문항 평균에 묻히면 어느 사례인지가
  안 보입니다. 필요한 것은 사례 이름입니다.

## 민감도

- **`chat_output_tokens`는 공급자가 사용량을 줄 때만 있습니다.** 없으면 그 사례는 건너뛰고, 모두 없으면 최대 줄도 적지 않습니다.
- **평가 코드만 바뀝니다.** `src/`가 그대로라 VM API는 다시 뜨지 않습니다.
