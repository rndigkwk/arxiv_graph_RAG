# ADR-102: 깨진 조건 판정은 원문이 아니라 모양을 남긴다

- **상태:** 채택
- **날짜:** 2026-11-05

## 맥락

[ADR-101](ADR-101-retry-a-broken-condition-verdict.md)은 깨진 조건 판정을 한 번 더 부르게 했습니다. 하지만 판정이 **왜** 깨지는지는
모릅니다. 11-02의 판정 한 번은 출력 128,424토큰을 썼는데, 무엇을 그렇게 길게 썼는지 남은 것이 없습니다. 실패 로그는
이유 코드 한 단어(`incomplete_content_verdict`)만 남깁니다.

원문을 남기지 않는 것은 일부러 정한 규칙입니다. `answer_validation.log_validation_failure`는 질문과 검색된 논문의 글을
기록하지 않습니다. 판정 출력에는 질문에서 따온 조건 문구와 논문 ID가 들어 있으므로, 원문을 남기면 그 규칙을 깹니다.

## 결정

판정을 읽지 못할 때마다 `condition_judge_unreadable` 한 줄을 남깁니다. 다시 부를 때도, 두 번 다 깨져 답을 되돌릴 때도
남깁니다. 값은 모두 숫자와 상태 이름입니다.

| 경우 | 남기는 것 |
|---|---|
| 읽을 수 없는 출력 | 출력 토큰, 응답 상태, 잘린 이유(`max_output_tokens` 등), 글자 수, 읽은 데까지가 JSON이었는지, `graph_conditions`·`candidates`의 길이와 같은 항목이 되풀이된 최대 횟수, 파싱 예외 이름 |
| 읽었지만 논문이 맞지 않음 | 기대한 수, 받은 수, 중복 수, 모르는 ID 수, 빠진 ID 수 |

"같은 조건을 2,000번 되풀이했다"와 "후보 하나를 빠뜨렸다"는 고칠 곳이 다릅니다. 앞은 출력 형식이고, 뒤는 지시문입니다.
이 두 경우는 위의 값만으로 가를 수 있습니다.

## 고르지 않은 것

- **원문의 앞뒤 일부를 남기기.** 원인은 가장 잘 보입니다. 하지만 위의 규칙을 깨고, CI 로그는 공개 저장소에서 누구나 봅니다.
- **평가 결과물에만 원문을 남기기.** 정기 평가 결과물도 내려받을 수 있습니다. 같은 문제가 남습니다.

## 민감도

- 모양만으로 원인이 가려지지 않으면, 그때 원문을 남길 다른 자리(로컬 평가에서만 켜는 설정 등)를 따로 정합니다.
