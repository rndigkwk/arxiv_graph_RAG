# ADR-009: 임베딩은 `text-embedding-3-large`를 유지한다

- **상태:** 채택
- **날짜:** 2026-10-16 (같은 날 Colab T4 파인튜닝 결과로 보강)
- **이 ADR은 중간 결론을 한 번 뒤집었습니다.** 아래 "뒤집힌 중간 결론" 참고.

## 맥락

로컬 임베딩 모델로 바꾸면 API 비용이 사라지고 파인튜닝이 가능해집니다. 후보는 인용으로
사전학습한 SPECTER2와 범용 BGE입니다.

## 결정

`text-embedding-3-large`를 유지합니다. 교체를 **품질 때문이 아니라 배포 부담 때문에** 보류합니다.

## 근거

| 후보 | 기준 모델 대비 | 판정 |
|---|---:|---|
| SPECTER2 (2020, 인용 사전학습) | **−0.0723** | 열세 |
| BGE (2023, 범용) | **−0.0109** (구간이 0 포함) | **동등** |

**전용 사전학습보다 모델 세대가 셌습니다.** 인용 과제인데 인용으로 사전학습한 모델이 범용
모델에 집니다. 모델을 고를 때 도메인 일치보다 **세대를 먼저** 보라는 신호입니다.

**그래서 품질은 교체를 막지 않습니다.** 110MB 로컬 모델이 API 모델과 구별되지 않습니다.
막는 것은 배포입니다.

| 항목 | 현재 | BGE 교체 시 |
|---|---|---|
| 앱 메모리 | **259MB** | + torch 런타임 + 모델 110MB |
| Streamlit 보장치 | 690MB | 초과 위험 |
| 질의 시 추론 | API 호출 | CPU 추론 (2코어 한도) |
| 한국어 혼용 질의 | 번역 생략 가능 | **번역 필수** ([ADR-010](ADR-010-korean-translate-only-when-needed.md)) |

## 뒤집힌 중간 결론

SPECTER만 보고 **"출발점 격차 때문에 로컬 분기 기각"** 이라고 적어 커밋했는데, BGE 측정이
그것을 뒤집었습니다. 출발점이 동등하면 파인튜닝은 0에서 시작해 무엇이든 벌면 API 모델을
넘습니다. **두 후보 중 하나만 보고 가지를 죽인 것이 잘못이었습니다.** 지우지 않고 남깁니다.

## 후속 측정 (2026-10-16) — 파인튜닝해도 넘지 못합니다

조건 ①을 바로 측정했습니다. Colab T4에서 BGE를 전체 파인튜닝한 뒤 같은 365질의로 채점했습니다.

| 모델 | recall@10 | `text-embedding-3-large` 대비 (쌍체 95% CI) |
|---|---:|---|
| `text-embedding-3-large` | 0.2019 | 기준 |
| BGE untuned | 0.1909 | −0.0109 [−0.0250, +0.0032] 0 포함 |
| BGE 파인튜닝 (in-batch) | 0.2051 | +0.0032 [−0.0115, +0.0188] **0 포함** |
| BGE 파인튜닝 (hard negative) | 0.2040 | +0.0022 [−0.0124, +0.0167] **0 포함** |

**파인튜닝은 untuned 대비 실재하는 개선입니다**(+0.0141 [+0.0081, +0.0209], 0 제외). 그런데 그
개선이 하는 일은 −0.0109의 격차를 메우는 것까지이고, **API 모델을 넘지는 못합니다.**

그래서 이 결정의 근거가 **더 강해졌습니다.** 이전에는 "동등하니 파인튜닝하면 넘을 수 있다"는
가능성이 열려 있었고, 지금은 그 가능성이 측정으로 닫혔습니다. 품질 이득이 0인데 torch 런타임과
110MB를 앱에 들일 이유가 없습니다.

**함께 적을 비교 하나.** 같은 365질의에서 CPU 선형 어댑터만 API 모델 대비 구간이 0을
제외합니다(+0.0110 [+0.0049, +0.0177], recall@10 0.2128 — [ADR-013](ADR-013-linear-adapter-offline-only.md)).
T4 3시간 파인튜닝은 그러지 못했습니다. 서로 다른 쌍체 비교이므로 "어댑터가 파인튜닝을 이긴다"로
적지는 않습니다. 적을 수 있는 것은 **GPU를 쓴 쪽만 유의성을 얻지 못했다**는 것입니다.

## 민감도

**조건 ①은 위에서 닫혔습니다.** 남은 것은 둘입니다.

1. ONNX int8 변환으로 메모리가 690MB 안에 들어오면 배포 장벽이 내려갑니다. 단 품질 이득이
   없는 지금은 들일 이유도 없고, 그것은 dograg의 해결 경로를 반복하는 것입니다.
2. 측정 비용 자체가 제약입니다 — CPU 인코딩이 SPECTER 12,264초, BGE 12,594초(각 3시간 30분
   내외)로 **제 추정의 8배**였습니다.
