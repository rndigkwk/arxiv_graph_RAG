# ADR-124: 배포된 공동인용 예측 모델을 매달 지난달 라벨로 다시 잰다 — 재학습은 아직 하지 않는다

- **상태:** 채택
- **날짜:** 2026-11-11

## 맥락

`graph-text-gbm`은 2026-10-14 스냅샷으로 학습해 고정돼 있습니다([ADR-031](ADR-031-the-model-that-wins-is-the-forecast.md)·[038](ADR-038-the-forecast-panel.md)).
그래프는 주간 수집으로 자랍니다([ADR-104](ADR-104-weekly-ingest-runs-on-the-vm.md)). 11-11 VM 그래프의 인용자는 7,635편이고,
그중 2026-09 이후가 3,877편입니다. 모델은 이 논문들을 학습 때 보지 못했습니다.

포트폴리오 검토에서 "학습 → 서빙 → 감시 → 재학습 루프가 없다"는 지적을 받았습니다.
재학습부터 자동으로 돌리면 두 가지를 모릅니다. 지금 모델이 나빠졌는지, 그리고 한 달 치 라벨이 판정할 만큼 나오는지입니다.
그래서 감시를 먼저 둡니다.

## 결정

- **매달 3일 04:19 UTC에 VM이 지난달을 잽니다**(`deploy/vm/forecast_monitor.sh`, `arxiv-forecast-monitor.timer`).
  api 이미지로 컨테이너를 한 번 띄우고, 그래프는 **읽기 전용 세션**으로 읽습니다. 유료 호출은 없습니다.
- **과제는 학습 평가와 같고, 창만 한 달입니다**(`models/link_prediction/monitor.py`).
  - 피처는 그 달보다 앞선 인용자의 공동인용 그래프에서 만들고, 라벨은 그 달 인용자가 새로 만든 공동인용입니다.
  - 순위 과제(앵커 1 + 같은 분야 미끼 9, 3,000 그룹)와 피처는 `dataset`의 함수를 그대로 씁니다.
  - 배포 모델은 앱이 읽는 파일(`models/artifacts/`)을 지문을 맞춰 읽습니다.
- **판정은 승격과 같은 함수입니다**(`pipeline.model_registry.judge`). 최고 휴리스틱 대비 쌍체 구간이 0을 제외하고, MRR이 0.60 이상이어야 합니다.
  - 넘으면 `ok`, 못 넘으면 `below_bar`, 그룹이 300개보다 적으면 판정하지 않고 `insufficient`입니다.
- **알림:** `/api/health`의 `forecast_monitor`가 결과를 보이고, 배포 점검(8시간마다)이 `below_bar`·실패·40일 넘게 돌지 않음을 실패로 셉니다.
  실패하면 기존 알림 이슈가 열립니다([ADR-106](ADR-106-alert-when-the-vm-ingest-stops.md)과 같은 길).
  한 번도 돌지 않은 상태는 문제로 세지 않습니다.
- **수집과 겹치지 않습니다.** 주간 수집의 잠금을 최대 2시간 기다린 뒤 읽습니다.

## 측정

11-11에 VM에서 2026-10을 쟀습니다(머지 전, 따로 복사한 모듈로, 읽기 전용).

| | 값 |
|---|---|
| 앞선 인용자 / 그 달 인용자 | 5,622 / 1,725 |
| 새 공동인용 라벨 / 쓸 수 있는 것 | 225,926 / 204,744 |
| 순위 그룹 | 3,000 |
| `graph-text-gbm` MRR · hits@5 | **0.6614** · 0.9013 |
| `adamic-adar` MRR (최고 휴리스틱) | 0.6302 |
| 휴리스틱 대비 | **+0.0312 [+0.0215, +0.0406]** — 0 제외 |
| 판정 | `ok` |
| 시간 · 최대 메모리 | 55초 · 775MB |

**모델은 아직 기준 위입니다. 다만 휴리스틱 대비 우위가 학습 평가의 +0.0818에서 +0.0312로 줄었습니다.**
MRR 자체는 0.6513보다 높습니다. 휴리스틱이 0.5696에서 0.6302로 더 많이 올랐습니다.
그래프가 조밀해져 공통 이웃만으로도 맞히기 쉬워진 것으로 읽습니다. 다만 한 달 측정이라 추세라고 말하지 않습니다.
이 차이가 줄어드는지가 재학습을 결정할 근거입니다.

## 고르지 않은 것

- **재학습을 바로 자동화하기.** 위 측정 전에는 한 달 라벨이 충분한지, 모델이 나빠졌는지 몰랐습니다. 재학습은 다음 단계에서 다룹니다.
  그때는 휴리스틱만이 아니라 **지금 모델(챔피언)과도** 같은 창에서 비교해야 합니다.
- **MLflow에 기록하기.** VM `.env`에 DagsHub 토큰이 없고, 감시에는 보고서 파일과 health로 충분합니다.
- **임베딩 전부를 받아 학습 평가처럼 `PaperTable`을 만들기.** 4만여 행 × 768을 파이썬 객체로 받으면 800MB가 넘습니다.
  순위 과제에 나온 논문 것만 받습니다.
- **스냅샷을 새로 떠서 재기.** 학습은 S2 역채움 때문에 스냅샷만 읽습니다(`pipeline/snapshot.py`). 감시는 학습하지 않고,
  같은 시점의 그래프에서 피처와 라벨을 함께 읽으므로 역채움이 둘에 똑같이 들어갑니다.

## 민감도

- **최대 메모리 775MB입니다.** 11-11에 VM의 여유 메모리는 1.5GB였습니다. 그래프가 자라면 공동인용 쌍이 늘어 메모리도 늘어납니다.
  보고서에 숫자가 남지 않으므로, 커지면 `journalctl -u arxiv-forecast-monitor`의 OOM으로 드러납니다.
- **라벨 달의 인용이 덜 들어와 있을 수 있습니다.** S2는 새 논문의 참고문헌을 늦게 채웁니다(ADR-104). 지난달을 재므로 라벨이 덜 찰 수 있지만,
  그룹 3,000은 10월에 다 찼습니다.
- **`models/`가 바뀌어 머지하면 VM API가 다시 뜹니다**([ADR-107](ADR-107-restart-the-api-only-when-it-reads-the-change.md)).
- **타이머는 머지 뒤 손으로 한 번 설치합니다**(`deploy/vm/install_forecast_monitor_timer.sh`). 설치 전에는 `unknown`입니다.
