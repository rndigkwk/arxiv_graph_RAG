# ADR-010: 한국어는 혼용은 그대로, 순수 한국어만 번역한다

- **상태:** 채택
- **날짜:** 2026-10-15

## 맥락

앱은 한국어 질문에 `translate_to_english`를 먼저 부르도록 프롬프트에 적혀 있었습니다. 그런데
**평가 케이스 71건이 전부 영어**였습니다 — 문서에 적어 둔 기능이 한 번도 측정되지 않은
상태였습니다.

## 결정

현재 설계(필요할 때 번역)를 유지합니다. 번역을 걷어내지도, 항상 걸지도 않습니다.

## 근거

케이스 61건을 두 형태의 한국어로 만들어 다섯 경로를 같은 정답으로 채점했습니다.

| 질문 유형 | `english` | `mixed_direct` | `mixed_translated` | `pure_direct` | `pure_translated` |
|---|---:|---:|---:|---:|---:|
| `exact-title` (21) | 1.000 | **1.000** | 1.000 | **0.809** | **1.000** |
| `topic` (10) | 1.000 | **1.000** | 1.000 | **0.800** | **1.000** |

**혼용 한국어에는 번역이 불필요합니다** — `mixed_direct`가 영어와 동일한 1.000입니다
(`text-embedding-3-large`가 다국어라서 영어 용어가 섞인 한국어를 그대로 처리합니다).

**순수 한국어는 19~20%를 잃고 번역이 전부 회복합니다** — 1.000 → 0.809 → 1.000.

**번역은 원문을 복원하지 않지만 성능은 회복합니다.** 번역 결과가 원문과 일치한 비율은
0.197 / 0.262뿐인데 검색은 1.000으로 돌아옵니다. 중요한 것은 표현의 일치가 아니라 의미의
등가입니다.

## 대가

순수 한국어 질문에 LLM 호출 한 번의 지연과 요금이 붙습니다.

## 민감도

**영어 전용 임베딩으로 바꾸면 번역이 필수가 됩니다**([ADR-009](ADR-009-keep-openai-embedding.md)).
이 측정이 그 비교표에 주는 값은 "번역 단계 자체는 품질을 잃지 않는다(0.809 → 1.000)"이고,
따라서 그 세금은 정확도가 아니라 **질문당 LLM 호출 하나**입니다.

**19~20%는 하한입니다.** 한국어를 모델이 생성했으므로 같은 계열 모델이 되돌리는 왕복이 실제
사용자보다 쉽습니다.
