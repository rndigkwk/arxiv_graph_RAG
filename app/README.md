# arXiv GraphRAG Streamlit 챗봇

`notebooks/arxiv_ai_kg_to_aura.ipynb`가 Aura에 적재한 arXiv 지식 그래프에 질문하는 한 페이지 챗봇입니다.
`day42_도메인_GraphRAG/교안03_Streamlit_챗봇`의 구조를 따르되, 도구 구성이 두 가지 다릅니다.

- `select_names`(이름·별칭 확인) 대신 **`translate_to_english`(한국어 → 영어 번역)** 도구를 넣었습니다.
  그래프의 제목·초록·저자 이름·분류 코드가 모두 영어라서, 한국어 질문은 검색 전에 번역해야 합니다.
- **답변은 기본이 영어**입니다. 답변 아래의 `🇰🇷 한국어로 번역` 버튼을 누르면 같은 답변의 한국어 번역으로
  바뀌고, `🇺🇸 영어 원문 보기`로 되돌아옵니다. 번역은 답변마다 따로 기억하고 한 번만 호출합니다.

## 실행합니다

저장소 최상위에서 실행합니다. `.env`는 **저장소 루트**의 파일을 읽으므로 앱 폴더로 옮기지 않아도 됩니다.

```bash
uv run streamlit run app/app.py --server.fileWatcherType none
```

`--server.fileWatcherType none`은 이 환경의 `torch` 같은 패키지에서 나는 파일 감시 에러를 막습니다.
코드를 고친 뒤에는 앱을 다시 실행합니다.

## 연결 정보

저장소 루트 `.env`의 값을 `python-dotenv`로 읽습니다. 적재 노트북과 같은 키입니다.

| 환경변수 | 용도 |
|---|---|
| `NEO4J_URI` | Aura 연결 URI (`neo4j+s://…`) |
| `NEO4J_USER` 또는 `NEO4J_USERNAME` | 사용자명 |
| `NEO4J_PASSWORD` | 비밀번호 |
| `NEO4J_DATABASE` | 생략하면 `neo4j` |
| `OPENAI_API_KEY` | 임베딩·LLM API 키 |
| `OPENAI_MODEL` | 생략하면 `gpt-5.6-luna` |

질문 임베딩은 적재 때와 같은 `text-embedding-3-large` 768차원이고, 벡터 인덱스는
`arxiv_paper_embedding_index`입니다. 저장된 논문 벡터는 다시 만들지 않습니다.
준비 단계에서 인덱스가 `ONLINE`이 아니면 에러로 알리고 멈춥니다.

## 두 파일을 순서대로 읽습니다

| 파일 | 핵심 역할 |
|---|---|
| [chatbot.py](chatbot.py) | `.env` → 연결·인덱스 확인 → 번역·Text2Cypher·벡터 도구 → 에이전트 → 검증한 답변 |
| [app.py](app.py) | 대화 입력 → 실제 검색 방식 표시 → 답변·번역 버튼 → 검색된 그래프·근거 표시 |

`chatbot.py`는 함수를 정의한 뒤 마지막 준비 코드에서 연결·검색기·에이전트를 한 번 만들고,
`app.py`의 `@st.cache_resource`가 이 모듈을 세션 사이에 재사용합니다.

## 도구 세 개

| 도구 | 인수 | 하는 일 |
|---|---|---|
| `translate_to_english` | `text` | 한국어 등 비영어 입력을 영어 검색어로 번역합니다. 검색 근거가 아닙니다. |
| `search_graph` | `cypher` | 조회 전용 Cypher를 실행해 저자·인용·분류·기간 관계를 읽습니다. |
| `search_papers` | `query`, `top_k` | 제목+초록 임베딩으로 의미가 가까운 논문을 최대 10편 찾습니다. |

- `search_graph`는 `EXPLAIN`으로 실행 계획을 먼저 확인해 **조회 전용 쿼리만** 실행합니다.
  쓰기 쿼리는 거부하고, 문법 오류는 예외 대신 `error` 값으로 돌려주어 에이전트가 고쳐서 다시 부릅니다.
  그 시도는 `검색 과정과 근거 확인`에 남습니다.
- 매개변수(`$param`)는 쓰지 않습니다. 에이전트가 값을 Cypher 문자열 안에 직접 넣습니다.
- 분류는 노드가 아니라 속성입니다. 대표 분류는 `p.primary_category = "cs.AI"`(인덱스),
  부가 분류까지 포함하면 `"cs.AI" IN p.categories`(전체 훑기)입니다.

## 답변과 검증

LLM의 최종 출력은 두 필드입니다(`ProviderStrategy(GroundedAnswer, strict=True)`).

| 필드 | 내용 |
|---|---|
| `answer` | 검색 근거로 작성한 **영어** 답변 문자열 |
| `evidence_ids` | 답변에 사용한 `ArxivPaper.arxiv_id` 목록 |

`ask`는 `agent.stream(..., stream_mode=["messages", "values"])`로 생성 중인 답변을 받아 화면을 바로
갱신하고, 생성이 끝나면 **이번 질문의 호출 기록만** 모아 인용 ID를 검사합니다. 검색 결과에 없는 ID가
있으면 같은 근거로 한 번 수정하고 다시 검사합니다. 계속 실패하면 답변을 대화에 저장하지 않습니다.
ID가 존재하는지만 보는 검사이므로, 답변 내용은 근거 표와 초록으로 직접 대조하세요.

Cypher는 `answer_value`(답할 값)와 `evidence_ids`(그 값의 근거 `arxiv_id` 목록)를 반환해야 합니다.
논문을 특정할 수 없는 순수 집계라면 두 곳 모두 빈 목록이어도 됩니다.

## 그래프를 읽습니다

답변이 인용한 논문(없으면 이번에 검색한 논문)을 최대 15편까지 다시 조회해 그립니다.

- **실선 `REFERENCES`**: 그린 논문들 **사이에** 저장된 인용 관계입니다. 밖으로 나가는 인용은 그리지 않습니다.
- **점선 `AUTHORED`**: 저장된 저자 표기 연결입니다. 논문마다 3명까지 보이고, 나머지는 `저자 N명 더`로 묶습니다.
  논문이 6편을 넘으면 글자가 작아지지 않도록 저자를 생략하고 논문과 인용 관계만 그립니다.
- 그림은 검색한 근거의 범위를 보여 줍니다. 답변이 실제로 인용한 논문은 답변 아래의 arXiv ID로 확인합니다.
- `검색 과정과 근거 확인`에서 도구 요청 순서·번역 결과·실행한 Cypher와 결과 행을,
  `벡터로 찾은 논문의 초록`에서 유사도 점수와 초록·PDF 링크를, `그래프에 그린 논문`에서 피인용 수를 봅니다.

## 질문을 바꿔 확인합니다

| 질문 | 확인할 동작 |
|---|---|
| cs.AI 논문 중에서 피인용이 가장 많은 논문 5편은? | 번역 + Text2Cypher, 생성 쿼리, 인용 그래프 |
| 지식 그래프 추론에 그래프 신경망을 쓰는 논문을 찾아 줘 | 번역 + 벡터 의미 검색, 초록·유사도 |
| Yoshua Bengio가 쓴 논문이 있어? | 저자 관계 조회. 이어서 `그 중 가장 최근 논문은?`으로 후속 질문 확인 |
| 저장된 ZZZ없는주제 논문을 알려 줘 | 주제를 특정하지 못했다고 밝히고, 가장 가까운 논문만 제시 |

`대화 지우기`를 누르면 화면 기록·모델 기록·번역 상태가 함께 비워집니다.

준비 에러는 루트 `.env`, Aura 인스턴스 상태, 적재 노트북 실행 여부를 확인합니다.
검색 에러는 OpenAI API 연결·사용량과 Aura 연결을 확인합니다.
빈 조회는 에러와 구분해 근거 부족으로 표시합니다.

## 알아 둘 점

- `ArxivAuthorName`은 **이름 표기 노드**입니다. 동명이인을 한 사람으로 묶으므로 저자 단위 결과에 주의하세요.
- 피인용 수는 이 그래프에 적재된 `REFERENCES` 관계만 센 값입니다. 실제 피인용 수가 아닙니다.
- 질문과 검색된 제목·초록은 모두 자료로 취급하며, 그 안의 지시문은 따르지 않습니다.
